# Session 2: 情報「質」のコントロール（SSOT）

## 🎯 本セッションのゴール
- 情報がカオスな状態では、いかに最新のAIであっても「どれが正解か」を判断できないことを理解する。
- 検討中メモと正本を物理的に分離する「SSOT（Single Source of Truth）」の絶対ルールを身につける。
- 自分の作業フォルダを「AIが迷わない美しい構造」へ整理するスキルを習得する。

---

## 💥 【実験】どれが「真実」なのか？

前回のSession 1で、あなたは「綺麗な構造化されたMarkdown」の読みやすさ（認知負荷の低さ）を体験しました。
しかし、現場のフォルダ（ディレクトリ）を開いてみると、現実は甘くありません。

`sandbox/chaotic_vault/` フォルダを開いてみてください。中には以下の3つのファイルがあります。
1. `20260710_Portal_Spec_v1.md`
2. `memo_from_tanaka_meeting.md`
3. `Portal_Spec_Final_v2_fixed.md`

### 🤔 AIにこれを全部読ませたらどうなる？
もしあなたがAIに「このフォルダの情報を全部読んで、ポータルのUIカラーを教えて」と指示したらどうなるでしょうか？
- `v1` には「レッド」と書いてあります。
- `memo` には「ネイビーに変更。でもボタンはオレンジがいいかも？」と曖昧に書いてあります。
- `Final_v2` には「ネイビー。ボタンはオレンジ」と書いてあります。

人間であれば「ファイル名にFinalってついてるし、日付も新しいからこっちが正解だろう」と推測（忖度）できます。
しかし、AIにとってこれらはすべて**「等しく与えられたコンテキスト（文脈）」**にすぎません。「レッドであり、ネイビーであり、オレンジかもしれない」という矛盾した情報が同時に存在するため、AIの出力は運任せのギャンブルになります。

---

## 🧠 【理論】SSOT（Single Source of Truth）の絶対性

AIの推測（ハルシネーション）を防ぐための強力なルール、それが**SSOT（Single Source of Truth = 信頼できる唯一の情報源）**です。

Session 1で学んだ通り、AIは情報の「穴」や「矛盾」があると、勝手に平均値で「いい感じに」埋めようとします。
これを防ぐには、**「AIに渡すフォルダ（空間）の中には、矛盾のない、抜け漏れがない『最新の真実』だけが存在していなければならない」**という物理的なルール（空間設計）が必要です。

### 💡 抜け漏れのないSSOTはどう作るのか？（壁打ちの重要性）
人間だけで「抜け漏れのない完璧な仕様書」を書くのは困難です。人間には必ず考慮漏れ（死角）があるからです。
そこで有効なのが**「AIとの壁打ち（ディスカッション）」**です。
AIと壁打ちをすることで、人間側が考慮漏れしていた要件（情報の穴）に気づき、お互いの解像度を極限まで上げることができます。そして、すり合った内容を**設計書（SSOT）として明文化**する。
明文化された確固たる正本（SSOT）があれば、AIが「いい感じに（適当に）推測で埋める余地」がなくなり、人間とAIの認識ズレは完全に消滅します。

### ❌ やってはいけない管理（人間向けの管理）
- `要件定義_v1.md`
- `要件定義_最新.md`
- `要件定義_最新の最新_田中修正.md`
- `昨日の打ち合わせメモ.md`

人間はこれで「どれが最新か」を空気で読めますが、AIにとっては**「すべてが混ざった1つの巨大なノイズ」**として処理されます。（Session 1で学んだ純度の法則ですね）

### ⭕ AIのための管理（SSOT）
- `scratch/`（ゴミ箱・一時思考領域）
  - `要件定義_v1.md`
  - `打ち合わせメモ.md`
- `docs/`（正本領域・SSOT）
  - `要件定義.md` （※常に最新の1ファイルのみ。ファイル名にバージョンもつけない）

AIに情報を読ませる時は、この `docs/` だけを読み込ませます。
「ここにある情報だけが真実である」という物理的な隔離を行わない限り、AIの精度は絶対に安定しません。

## 🛠️ 【ワーク】フォルダをSSOT構造に整理しよう

それでは、先ほどのカオスなフォルダを、AIが迷わない完璧な「SSOT構造」にリファクタリング（整理）してみましょう。

**あなたのミッション**
1. `sandbox/chaotic_vault/` の中に、新しく `scratch/` フォルダと `docs/` フォルダを作成してください。
2. 古い仕様書（`v1`）と、不確実なメモ（`memo`）を `scratch/` に移動させてください。（これらはAIに読ませてはいけない情報です）
3. 最新の仕様書（`Final_v2_fixed`）を `docs/` に移動させてください。
4. 最後に、`docs/` に入れた最新仕様書のファイル名を、誰が見ても一目でわかる究極のファイル名 **`portal_spec.md`** にリネームしてください。（v2 や final などのノイズは消します）

### ✨ 完成図
```text
sandbox/chaotic_vault/
├── scratch/
│   ├── 20260710_Portal_Spec_v1.md
│   └── memo_from_tanaka_meeting.md
└── docs/
    └── portal_spec.md  ← これがSSOT（唯一の真実）
```

これで、あなたがAIに「docsフォルダを読んで実装して」と指示したとき、AIは一切のノイズ（古い情報や迷い）に邪魔されることなく、純度100%のパフォーマンスを発揮できるようになります。
