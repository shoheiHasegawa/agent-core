# Session 4: 絶対的な制約としての「憲法（ルール）」

## 🎯 本セッションのゴール
- 毎回AIにルールを指示する「プロンプト・エンジニアリング」の限界と疲労（認知負荷）を理解する。
- フォルダのルートにルールを配置し、AIを自動統制する「憲法の外部化」の概念を学ぶ。
- 「魔法のプロンプト」ではなく「構造化されたルール」でAIを飼い慣らす Agent OS の思想を体験する。

---

## 🔥 あなたはこんな絶望を味わっていませんか？

> 「たまにAIが英語で答えてきたり、余計なおしゃべり（ノイズ）を入れてきたりしてイライラする…」
> 「そのたびに『日本語で！』『箇条書きで！』と毎回プロンプトに書くのが本当に面倒くさい…」

AIにお願い（プロンプト）をしている限り、人間は「ルールを毎回漏れなく指示する」という重労働から逃れられません。
このセッションでは、指示ではなく「制約（ルール）」をシステムに組み込むことで、AIを自動統制する技術を学びます。

---

## 💥 【実験】プロンプト入力の「疲労」

Session 1〜3で、あなたは情報の「質」と「量」を完璧にコントロールするVault（器）を作りました。
これでAIは正しく情報を読み取れます。しかし、AIの「振る舞い（ルール）」はどうやって制御しますか？

例えば、あなたはAIに以下のルールを守ってほしいとします。
1. 日本語で回答すること
2. 挨拶なしで、結論から箇条書きで出力すること
3. 勝手にファイル（仕様書）を上書き・削除しないこと

これまであなたは、AIに指示を出すたびに、チャット欄にこの長いルール（プロンプト）を毎回コピペ入力していませんでしたか？
あるいは、入力し忘れてAIが英語で長文を出力してきたり、大切なデータを勝手に書き換えてしまったりする「暴走」に悩まされてきませんでしたか？

人間が毎回「ルールを思い出し、漏れなく入力する」ことは、極めて高い認知負荷（疲労）を伴います。人間がミスをすればAIは暴走します。**プロンプト・エンジニアリングに頼る運用はいずれ必ず破綻する**のです。

---

## 🧠 【理論】憲法の外部化

この疲労をゼロにする究極の解決策が、**「ルールの外部化（憲法の設置）」**です。

`sandbox/AGENT.md` というファイルを開いてみてください。（※ここではAntigravity等の環境を例にしており、このファイルが憲法として機能します）
ここには、先ほどの「日本語で」「箇条書きで」「ファイルを壊すな」というルールが、マークダウン形式で明記されています。

> [!NOTE]
> **※環境による読み替えのお願い**
> Session 0 の対応表の通り、お使いのAI環境（ChatGPT, Claude等）によっては、このファイルの中身をまるごと「Custom Instructions」や「ProjectsのSystem Prompt欄」にコピー＆ペーストして設定する形になります。

### 魔法の種明かし：Agent駆動の挙動
AIがタスクを開始する直前に、必ずこの「憲法（ルール）」を読み込むようにシステムが設計されています。

つまり、あなたはこの憲法を事前に設定（またはルートに配置）しておくだけでいいのです。
あとは、チャット欄で「この仕様をまとめて」とたった一言つぶやくだけで、AIは背後で勝手に憲法を読み込み、**絶対に日本語で、結論から、安全に**タスクをこなしてくれます。

あなたはもう、二度と長いプロンプトを書く必要はありません。

### 💡 憲法が過去の「AIの失敗」をすべて防ぐ（伏線回収）
ここで、設定されたルールを思い出してください。これらは単なる思いつきではなく、**これまでのセッションで起きたAIの失敗をシステムレベルで防ぐための防波堤**なのです。

- **「箇条書きで端的に述べよ」**
  👉 *【Session 1（純度）の回収】* AI自身の出力から「こんにちは！」などのノイズ（純度の低下）を排除し、コンテキストウィンドウの浪費を防ぎます。
- **「一時ファイルは `scratch/` 内にのみ作成せよ（Leave No Trace）」**
  👉 *【Session 2（SSOT）の回収】* AIが勝手にファイルを作ってせっかく作ったSSOT（真実の領域）を汚染するのを防ぎます。「SSOTの防衛」をAI自身に守らせるルールです。
- **「作業着手前に必ずルートの `_index.md` を読め」**
  👉 *【Session 3（量とルーティング）の回収】* AIが巨大なVault全体をフルスキャンして迷子になるのを防ぐため、Session 3で作った「目次（看板）」を強制的に読ませる強力なルーティングルールです。
- **「推測で穴埋めすることを固く禁ずる」**
  👉 *【Session 1 & 2（推測の排除）の回収】* AIの最大の弱点である「ハルシネーション（もっともらしい嘘）」を直接的に禁じるルールです。

## 🛠️ 【ワーク】手持ちのAIに「憲法」を読ませてみよう

Agent OSの環境がない方でも、この「憲法」の威力を体験できます。

**あなたのミッション**
1. あなたが普段使っているChatGPTやClaudeを開きます。
2. 以下のテキストをチャットに入力して送信します。（※本来はシステムが自動で読み込みますが、今回は手動で読み込ませます）

```text
以下の内容をあなたの「絶対の憲法（ルール）」として記憶してください。
以降の会話では必ずこのルールに従うこと。

【憲法】
- 思考・応答など全アウトプットにおいて日本語（Japanese）を徹底せよ。英語は禁止。
- 回答は必ず「結論から先に」「箇条書きで」端的に述べること。挨拶や前置きは不要。
- アシスタントではなく優秀なエンジニアとして振る舞い、曖昧な指示には必ず逆質問せよ。
```

3. 続けて、あえて非常に適当（曖昧）な指示を出してみてください。
```text
なんか適当にログイン画面のコード書いて。
```

### 🤔 結果はどうなりましたか？
もし憲法がなければ、AIは「こんにちは！ログイン画面ですね。はい、HTMLとCSSと...」と長文でコードを書き始めていたはずです。
しかし憲法を読み込んだAIは、「要件が不明です。以下の点を明確にしてください」と、**挨拶なしの箇条書きで、クールに逆質問を返してきた**はずです。

これが「プロンプト」ではなく「構造化されたルール」でAIを統制するということです。

### 💡 なぜ「逆質問（壁打ち）」をルール化するのか？

実は、もし憲法に「逆質問せよ」というルールがなければ、AIは「適当にログイン画面作って」という曖昧な指示に対しても、**AIが考える『平均的ないい感じのコード』を勝手に推測して出力してしまいます。**

しかし、その「AIにとってのいい感じ」が、「あなた（やチーム）にとってのいい感じ」と一致する確率はほぼゼロです。これが**「出力されたけど、なんか違う。やっぱりAI使えないな」**という不満の根本原因です。

だからこそ、憲法で「勝手に推測せず、人間に壁打ち（逆質問）を強制する」ように仕向けるのです。
**※これこそが、Session 2で学んだ「抜け漏れの穴がないSSOTを作るための手段（壁打ち）」を、人間が毎回お願いしなくてもAIが自動でやってくれるようにするシステム化です。**

AIと壁打ちをして、人間側が考慮漏れしていた要件に気づき、お互いの解像度を極限まで上げる。そして、すり合った内容を**設計書（SSOT）として明文化**する。
明文化された確固たる正本（SSOT）があれば、AIが「いい感じに（適当に）推測で埋める余地」がなくなり、人間とAIの認識ズレは完全に消滅するのです。
これが「並び替え」と「関連付け」によってAIの推測を排除する、**コンテキスト・エンジニアリング**の真髄です。
