# Session 5: 役割と手順の分離（SKILLの活用）

## 🎯 本セッションのゴール
- すべてのルールを憲法（`AGENT.md`）に詰め込むと、AIが混乱しアテンションを失うことを理解する。
- 憲法（グローバルルール）と手順書（SKILL）を物理的に分離する「職務分離の原則」を学ぶ。
- Agent OS の真髄である「モジュール化されたAIの拡張機能（SKILL）」の概念を体得する。

---

## 💥 【実験】分厚すぎるマニュアルの弊害

Session 4で、あなたは「ルールの外部化（AGENT.md）」によってプロンプトの疲労から解放されました。
すると、人間はこう考えます。
「よし、それなら『コードレビューの手順』も『DB設計のルール』も『議事録の書き方』も、全部この `AGENT.md` に書いておこう！そうすれば最強のAIになるぞ！」

`sandbox/AGENT_bloated.md` を開いてみてください。
あらゆる業務マニュアルが詰め込まれ、見事に肥大化した「最悪の憲法」が出来上がっています。

### 🤔 AIにこの分厚い憲法を読ませたら？
もしあなたが、このAIに対して「この仕様書をレビューして」とお願いしたらどうなるでしょうか？

AIの脳（コンテキストウィンドウ）には、「コードレビューのルール」「DB設計のルール」「議事録の書き方」がすべて同時にロードされています。
情報量（ノイズ）が多すぎるため、AIのアテンション（注意力）が分散し、**「仕様書のレビューを頼まれたのに、なぜかDB設計の提案をしてくる」「なぜか議事録フォーマットで出力してくる」**といったハルシネーション（混乱）を引き起こします。

これは、新入社員に1000ページの業務マニュアルを丸投げして「これ全部読んでから仕事してね」と言うのと同じです。人間でもパニックになりますよね。

---

## 🧠 【理論】職務分離（Separation of Duties）の原則

この混乱を防ぐためのアーキテクチャが、You_Inc Agent OSのコア概念である**「SKILL（役割と手順の分離）」**です。

ルールには、大きく分けて2つの種類があります。
1. **いつでも絶対に守るべきルール**（日本語で話す、ファイルを壊さない等） 👉 これが **AGENT.md（憲法）**
2. **特定の作業をする時だけ必要なルール**（コードレビューの手順等） 👉 これが **SKILL（手順書）**

これらを物理的に別のフォルダに分離することで、AIは「今はコードレビューの仕事だから、基本憲法に加えて『コードレビュースキル』だけを取り出して読もう（JIT読み込み）」と自律的に判断できるようになります。
これにより、AIの脳のメモリには常に「今必要なルール」だけが存在する純度100%の状態が保たれます。

---

## 🛠️ 【ワーク】憲法からSKILLを切り出そう（リファクタリング）

それでは、肥大化した `AGENT_bloated.md` を分割し、美しい役割分担の構造を作りましょう。

**あなたのミッション**
1. `sandbox/` の中に、新しく `skills/code-reviewer/` というフォルダ構造を作成してください。
2. 肥大化した `AGENT_bloated.md` の中から「コードレビュー時の絶対ルール（10項目）」の部分だけを切り取ります。
3. 切り取った内容を、先ほど作ったフォルダの中に `SKILL.md` という名前で保存してください。（ファイルのパスは `sandbox/skills/code-reviewer/SKILL.md` になります）
4. 同様に、DB設計や議事録作成のルールも、本来は別のスキルとして切り出します（今回は切り取って削除するだけでも構いません）。

### ✨ 完成図
```text
sandbox/
├── AGENT.md （純粋な憲法だけが残る）
└── skills/
    └── code-reviewer/
        └── SKILL.md （レビュー手順だけが書かれた専門ファイル）
```

これこそが Agentic OS のアーキテクチャです。
あなたはAIに「プロンプト」で指示を出すのではなく、**「フォルダとファイルという空間設計」**によってAIの役割を定義（プログラミング）したのです。
