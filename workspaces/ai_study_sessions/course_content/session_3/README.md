# Session 3: 情報「量」のコントロール（ルーティングと粒度）

## 🎯 本セッションのゴール
- 情報が「正しくても長すぎる」場合、AIのアテンション（注意力）が低下しミスを起こすことを体験する。
- 巨大なドキュメントを意味の塊（モジュール）ごとに分割するスキルを身につける。
- **「ファイル名自体が究極の要約である」**という原則と、AIへのルーティング（誘導）の概念を理解する。

---

## 🔥 あなたはこんな絶望を味わっていませんか？

> 「プロジェクトの資料を全部AIに読み込ませたら、AIが混乱してアテンション（注意力）が吹き飛んだ…」
> 「結果として、一番大事な要件を見落とされて重大なバグに繋がった…」

情報を網羅すればするほど、AIは「情報の海」で迷子になります。
このセッションでは、AIを迷わせないための「情報の切り分け方（ファイル分割）」と「誘導（ルーティング）」の極意を学びます。

---

## 💥 【実験】広大な砂漠から針を探す

Session 2であなたは情報をSSOT（真実のみ）に絞り、壁打ちによって「抜け漏れ（穴）」を完璧に塞ぎました。
しかし、その副作用として何が起きるでしょうか？「あらゆる要件を網羅した完璧な仕様書（SSOT）」は、必然的に**巨大なファイル**へと肥大化していきます。

`sandbox/massive_vault/all_project_data_combined.md` を開いてください。
これが、SSOTにはなっているものの「全情報が1つにぶち込まれた」状態です。

**👉 ワーク：目視で探してみてください**
このファイルの中から、以下の2つの答えを探し出してください。
1. ボタンの色は何色ですか？
2. データベースのシステム名は何ですか？

いかがでしょうか。
ゴルフコンペの案内や、無駄に長いJSONコードの海をスクロールしながら、「あれ、どこだっけ？」と探すのは非常に面倒で脳が疲れませんでしたか？

### 🤔 AIにこの巨大ファイルを読ませたら？
「探すのが面倒ならAIに全部読ませて探させればいいじゃないか」と思うかもしれません。
しかし、AIにも**コンテキストウィンドウ（一度に処理できる文字数）の限界**があります。さらに重要なのが**「アテンション（注意力）の喪失」**です。

AIは入力された全テキストを計算対象とするため、無関係なJSONコードやゴルフコンペの案内に「思考力（計算リソース）」を奪われます。結果として、ファイルの中腹にポツンと書かれた「ボタンはオレンジ」という重要な要件を見落とす（あるいは過去のボツ案のレッドと混同する）確率が跳ね上がります。

人間がスクロールして疲れる巨大ファイルは、AIの脳をも確実に疲弊させるのです。

---

## 🧠 【理論】ファイル名による「ルーティング（誘導）」

この問題の解決策は、巨大なテキストを**「適切な情報の粒度（サイズ）」に分割すること**です。

もしファイルが以下のように分かれていたらどうでしょうか？
- `ui_spec.md`
- `infra_spec.md`
- `legacy_api_schema.json`

あなたがAIに「UIのカラーを教えて」と質問する時、AIはファイル名を見るだけで「あ、UIのことなら `ui_spec.md` だけを読み込めばいいな」と瞬時に判断できます。
インフラの仕様や無駄なJSONを読み込む必要がないため、AIのコンテキストウィンドウには「純度100%のUI情報」だけが入り、絶対にアテンションを失いません。

これこそが**「ファイル名自体が究極の要約（最も粗い粒度の情報）である」**というコンテキスト・エンジニアリングの極意です。

---

## 🛠️ 【ワーク】巨大ファイルを分割（モジュール化）しよう

それでは、先ほどの巨大ファイルを分割し、AIが迷わない美しい構造にリファクタリングしましょう。

**あなたのミッション**
1. `sandbox/massive_vault/` フォルダの中に、新しく `docs/` と `scratch/` フォルダを作ります。
2. 巨大ファイルの中から、「UIに関する確定要件」だけを切り出して `docs/ui_spec.md` を作成してください。
3. 同様に、「インフラに関する確定要件」だけを切り出して `docs/infra_spec.md` を作成してください。
4. 残りのゴルフコンペ案内や社長のスピーチ、ボツ案の議事録などのゴミはすべて `scratch/garbage.md` に隔離（または削除）してください。

### ✨ 完成図と「_index.md」の魔法
```text
sandbox/massive_vault/
├── scratch/
│   └── garbage.md
└── docs/
    ├── ui_spec.md
    └── infra_spec.md
```

これで完璧です！
しかしファイルが増えると、今度は「どのファイルに何が書かれているかの全体像」がわかりにくくなります。そこで我々Agent OSでは、ディレクトリのルートに **`_index.md`** という目次ファイルを作る運用を行います（今回は解説のみ）。

AIはまず `_index.md` を読み、「UIの話なら `ui_spec.md` を見に行こう」と自律的に動く（ルーティングする）ようになります。
