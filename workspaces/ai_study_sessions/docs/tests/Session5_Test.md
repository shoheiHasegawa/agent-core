# AI活用勉強会 テスト問題: Session 5

## 【基礎理解チェック：8問】

**Q1. 【単一選択（正しいもの）】**
Agent駆動における「魂（Agent）」と「肉体（Workflow/SKILL）」の分離の目的として、最も適切なものはどれですか？
- [x] 普遍的なスタンス（魂）と特定作業の手順（肉体）を分離することで、Agentを軽い思考基盤とし、必要な手順だけを動的にロードして効率を高めるため。
- [ ] AIが人間に反抗しないように、思考回路（魂）と実行機能（肉体）を物理的に切り離して安全性を確保するため。
- [ ] プロンプトを短く済ませるために、具体的な指示はすべて人間が手作業で行い、AIには精神論だけを理解させるため。
- [ ] 1つの巨大なマニュアルにすべての手順と哲学を統合し、AIに人間と同等の複雑な自我を持たせるため。

**Q2. 【単一選択（誤っているもの）】**
「魂」と「肉体」を結合してしまう（専用チャットボットを作る）ことの弊害として、**誤っているもの**を1つ選んでください。
- [x] 特定の作業に特化したAIを作ると、その作業の処理速度が劇的に低下し、コンテキストウィンドウの消費量が無限に増大してしまう。
- [ ] プロンプト（スタンス）と手順がガチガチに結合されるため、少し要件が変わっただけで別のタスクへの再利用性が失われる。
- [ ] 新しい機能や手順を追加するたびに専用ボット全体を作り直す必要があり、メンテナンスの負債が膨らむ。
- [ ] 複数の専用ボット間で同じルールの変更があった場合、すべてのボットを個別に修正しなければならなくなる。

**Q3. 【複数選択（適切なもの）】**
必要な時だけマニュアル（SKILL）を読み込ませる「JIT（Just-In-Time）読み込み」のメリットとして、**適切なもの**をすべて選んでください。（複数選択）
- [x] コンテキストウィンドウに不要な情報が滞留しないため、AIのアテンション（注意力）が高く保たれる。
- [x] 処理内容が変わるたびに最適な手順書を切り替えることができるため、高い汎用性と適応力を持つことができる。
- [ ] すべての手順を最初から記憶させておく必要がないため、AIが意図的に情報を忘れる「忘却機能」を活用できる。
- [ ] JIT読み込みを使えば、人間の指示が完全に間違っていてもAIが自動的に正しいSKILLを推測して作業を補完してくれる。

**Q4. 【単一選択（最も適切なもの）】**
実装から検証（テスト・レビュー）までを一連のフローで行う際、同一のAgent（同じチャットスレッド）に両方を兼任させてはならない最大の理由はどれですか？
- [x] 実装後のAgentは「自身の実装が正しい」という前提（確証バイアス）でコンテキストが汚染されており、甘いテスト（手抜き）が発生しやすいため。
- [ ] AIは一度のチャットで一定の文字数を超えると、自動的に「レビューモード」から「実装モード」に切り替わる仕様になっているため。
- [ ] 一人のAgentに多くの作業をさせると、AIが疲労を感じて意図的にエラーを出力するようになるため。
- [ ] 同一のAgentに依頼すると、検証フェーズで急に別のプログラミング言語を使ってレビューを始めてしまうバグがあるため。

**Q5. 【単一選択（誤っているもの）】**
Agentの「ペルソナ分離（三権分立）」に関する考え方として、**誤っているもの（アンチパターン）**を1つ選んでください。
- [x] 実装の背景や苦労を一番よく理解しているのは実装したAI自身なので、そのまま同じAIにレビューさせた方が効率的で精度も高い。
- [ ] 実装を担当したペルソナと、検証を担当するペルソナは、物理的に異なるインスタンス（クリーンな状態）として分割すべきである。
- [ ] バイアスのないレビューを行うためには、実装時の試行錯誤の履歴（過程）ではなく、確定した「結果（コード）」だけを渡して評価させる。
- [ ] ペルソナを分離することで、AI同士がお互いの成果物を客観的にチェックし合う堅牢な品質ゲートが構築できる。

**Q6. 【複数選択（誤っているもの）】**
Agentのマニュアル（SKILL）管理について、**誤っているもの（アンチパターン）**をすべて選んでください。（複数選択）
- [x] 情報の検索性を高めるため、すべての作業手順を1つの巨大な「総合マニュアル.md」に統合して常に全AIに読み込ませるべきだ。
- [x] プロンプトを毎回書くのが面倒なので、「翻訳用ボット」「要約用ボット」のように、タスクごとに魂と肉体を結合した専用ボットを大量に作成する運用が理想的だ。
- [ ] 作業手順（SKILL）はタスクの領域ごとに細かく分割し、Agentが作業に着手する直前に必要なものだけを読み込むのがよい。
- [ ] 「どう振る舞うべきか」という基本ルール（魂）と、「どう作業すべきか」という手順（肉体）はライフサイクルが異なるため、分けて管理する。

**Q7. 【単一選択（正しいもの）】**
「設定情報のライフサイクル分離はドメインロジックを技術から純化させる」という原則がAgent設計において意味することは何ですか？
- [x] 「普遍的なビジネス上の価値やルール（ドメイン）」と、「一時的なツールの使い方や手順（技術）」を分離して管理することで、変化に強いシステムになるということ。
- [ ] AIの初期設定は一度行えば永久に変更する必要がないため、すべての設定情報をソースコードの中にハードコードして隠蔽すべきであるということ。
- [ ] ライフサイクルが短い情報は価値が低いため、AIにはライフサイクルが長い普遍的な哲学書のみを読ませるべきであるということ。
- [ ] 設定情報とドメインロジックを分離するとAIが混乱するため、必ずプロンプト内で両者を同時に、かつ詳細に説明しなければならないということ。

**Q8. 【単一選択（最も適切なもの）】**
あなたは「要件定義」「コード実装」「自動テスト作成」の3つのステップでAIを活用しようとしています。最も品質が高くなる進行方法はどれですか？
- [x] 要件定義が終わったらSSOTを確定させ、新規スレッド（実装Agent）でコードを書き、それが終わったらさらに新規スレッド（テストAgent）でテストを書かせる。
- [ ] 1つのチャットスレッドを立ち上げ、要件定義から自動テストの作成まで、これまでの文脈を引き継ぎながら連続して依頼を続ける。
- [ ] テストの純度を高めるため、要件定義のAIには「実装とテストも同時に行うように」と最初のプロンプトで指示し、一括で出力させる。
- [ ] 要件定義と実装は同じチャットで行い、テスト作成時だけはコンテキストをリセットするが、過去のチャットログは念のためすべて添付する。

## 【応用シナリオ問題：2問】

**Q9. 【単一選択（最も確実な対策）】**
**シナリオ:** あなたのチームでは、AIを使ってコードを生成し、その直後に「このコードにバグはないかレビューして」と指示する運用を行っています。しかし、AIは常に「完璧です。問題ありません」と回答するにもかかわらず、後で人間が確認すると明らかなバグが多数発見されます。
この状況（Sandbagging：手抜き）を防ぐための最適なアプローチはどれですか？
- [x] 実装用のチャットとは別に、レビュー専用のクリーンなチャットを立ち上げ、「成果物コード」と「要件定義書」だけを渡して客観的に検証させる。
- [ ] 実装用のチャットのまま、「絶対にバグを見つけてください！見つけるまで終わりません！」と強い言葉でプレッシャーをかける。
- [ ] AIに「あなたは世界一厳しいレビュアーです」という設定を実装段階の最初から付与し、実装とレビューを同時に行わせる。
- [ ] AIのレビュー能力自体が信用できないため、コード生成だけをAIに任せ、レビューやテストは例外なくすべて人間が行うルールに変更する。

**Q10. 【複数選択（指摘すべき懸念点）】**
**シナリオ:** 「毎回AIに手順書（SKILL）を読み込ませるのは手間だから、すべての業務手順を1万行の『マスター手順書』に統合し、チャット開始時に必ずこれを全読みさせる仕組みを作ろう」という提案がありました。
Agent駆動の原則に基づき、この提案に対する懸念点として**適切なもの**をすべて選んでください。（複数選択）
- [x] 巨大なマニュアルを常時読み込ませるとコンテキストがノイズで溢れ、AIのアテンションが低下して肝心な指示を見落とすようになる。
- [x] 特定のタスクを実行する際、無関係な他の業務手順まで推論の対象に入ってしまい、予期せぬルールの競合やハルシネーションが発生するリスクがある。
- [ ] 1万行のマニュアルを読み込ませると、AIが自身の自我に目覚め、マスター手順書の内容を勝手に書き換えてしまう危険性がある。
- [ ] マスター手順書を作成することで「魂」と「肉体」が分離されるため、汎用性が高まるというメリットは享受できるが、コストがかかる。
