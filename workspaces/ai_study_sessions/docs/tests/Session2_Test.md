**テーマ:** 「SSOT（正本）」と壁打ち
**問題数:** 全10問（理解チェック8問、応用シナリオ問題2問）

## 【基礎理解チェック：8問】

**Q1. 【単一選択（正しいもの）】**
Agent駆動開発における「壁打ち（Sparring）」の最も重要な目的はどれですか？
- [x] 人間の曖昧な思考を言語化し、AIに勝手な推測（穴埋め）をさせないための明確な要件を定義すること。
- [ ] 最初から完璧なプロンプトを作成するためのテクニックをAIに学習させること。
- [ ] アイデア出しをすべてAIに委ね、人間は考える手間を省略して結果だけを受け取ること。
- [ ] 過去のすべてのチャット履歴をAIに読み込ませ、文脈を整理してもらうこと。

**Q2. 【単一選択（誤っているもの）】**
SSOT（Single Source of Truth：唯一の信頼できる情報源）の性質として、**誤っているもの**を1つ選んでください。
- [x] AIだけでなく人間にとっても心地よい、行間を読ませるような美しい文章構成で書かれている。
- [ ] プロジェクトの仕様や決定事項が、複数のファイルに分散せず1箇所に集約されている。
- [ ] AIが論理的かつ構造的に読み取れる（パースできる）状態が保たれている。
- [ ] 新しい決定事項があれば、口頭やチャットのログではなく、このドキュメント自体が更新される。

**Q3. 【複数選択（適切なもの）】**
AIに作業を依頼する際の情報の与え方として、**適切なもの**をすべて選んでください。（複数選択）
- [x] 散らばったメモをそのまま渡すのではなく、壁打ちを通じて要件を1つのSSOTにまとめてから実装を依頼する。
- [x] AIが文脈を誤解しないよう、機械可読性の高い（Markdownなどの）構造化されたフォーマットで情報を渡す。
- [ ] AIの文脈推測能力を活かすため、関連しそうな複数の古いファイルをそのまま丸ごと渡し、必要な情報を探させる。
- [ ] 途中で要件が変わった場合は、SSOTを更新する手間を省くため、チャットの会話内で追加の指示としてのみ伝える。

**Q4. 【単一選択（最も適切なもの）】**
AI時代のドキュメント設計において、最も優先すべき価値基準はどれですか？
- [x] 人間が読んで「見栄えが良い」ことよりも、AIが誤読なく正確に論理をパースできる「機械可読性」。
- [ ] AIが学習しやすいように、一般的なビジネス用語を避けて専門的なプログラミング言語のみで記述すること。
- [ ] 人間の思考プロセスをすべて残すため、決定に至るまでの雑多な議論の経緯もSSOT内に網羅すること。
- [ ] 視覚的な理解を助けるため、文字情報を極力減らし、図解やスクリーンショットを中心に構成すること。

**Q5. 【複数選択（誤っているもの）】**
AIを使った成果物作成に関する考え方で、**誤っているもの（アンチパターン）**をすべて選んでください。（複数選択）
- [x] 優良なプロンプトさえあれば、事前の壁打ちなしで最初から完璧な企画書やコードを「ワンパン」で出力できる。
- [x] 人間向けの美しいドキュメントこそが、AIにとっても最高のインプット（SSOT）になる。
- [ ] 不確実性の高いタスクでは、まずAIと対話して方針を固めるフェーズを設けることが成功の鍵となる。
- [ ] SSOTは一度作って終わりではなく、プロジェクトの進行に合わせて常に最新の状態に保たれるべきである。

**Q6. 【単一選択（正しいもの）】**
壁打ちの過程で得られた「重要な気づき」や「要件の変更」は、どのように扱うのがAgent駆動において正解ですか？
- [x] 現在進行中のチャットログに留めず、速やかにSSOT（正本ドキュメント）へ反映・更新する。
- [ ] チャットの履歴をさかのぼればAIも人間も確認できるため、特にドキュメント化せずそのまま作業を続ける。
- [ ] 過去の経緯として重要なので、現在のSSOTとは別に「変更履歴専用の長大なファイル」を作成してAIに読み込ませる。
- [ ] 次回のタスクから反映されるように、人間の手元の個人的なメモ帳にのみ記録しておく。

**Q7. 【単一選択（誤っているもの）】**
「Zettelkasten（知識管理）におけるAIとの共生」の概念において、**誤っているもの**を1つ選んでください。
- [x] 情報はとにかく「収集の場（Inbox）」に蓄積し続けることが重要であり、AIがそれを自動で価値ある知識に変換してくれる。
- [ ] Zettelkastenは単なる保管庫ではなく、情報を加工・蒸留していくプロセスそのものである。
- [ ] AIに対して自身の思考を説明するプロセス自体が、人間の知識の解像度を劇的に向上させる。
- [ ] AIとの対話（壁打ち）を通じて得られた抽象的な繋がりこそが、新たな知識の価値を生み出す。

**Q8. 【複数選択（正しいもの）】**
AIに「推測」をさせないために人間が負うべき責任として、**正しいもの**をすべて選んでください。（複数選択）
- [x] 曖昧な言葉や多義的な表現を避け、システム要件レベルで明確な言葉を選択すること。
- [x] 作業に必要な前提知識や制約条件を、推測に頼らなくて済むように明示的に提供すること。
- [ ] AIからの質問には答えず、AI自身にWeb検索などをさせて自力で最適解を見つけさせること。
- [ ] 細かい条件を人間が考えるのは非効率なので、「いい感じに仕上げて」と指示し、出力結果から要件を逆算すること。

## 【応用シナリオ問題：2問】

**Q9. 【単一選択（最も適切な行動）】**
**シナリオ:** チームで新しい機能の開発を進めており、Slackの複数のチャンネルと議事録に要件が散らばっています。あなたはAIを使ってこの機能のコードを実装しようとしています。最初にとるべき行動として最も適切なものはどれですか？
- [x] 散らばった情報を一つのMarkdownファイル（SSOT）にまとめ上げ、矛盾や抜け漏れをAIと壁打ちして解消してから実装フェーズに入る。
- [ ] AIの処理能力を活かし、関連するすべてのSlackログと議事録のファイルをプロンプトに一括添付して「これを元に実装して」と指示する。
- [ ] 人間が要件をまとめるのは時間の無駄なので、一番詳しそうな議事録を1つだけAIに渡し、足りない部分は推測で補わせる。
- [ ] 開発効率を優先し、SSOTの作成は後回しにして、とりあえず見切り発車でAIにコードを書かせながら要件を調整していく。

**Q10. 【複数選択（指摘すべき懸念点）】**
**シナリオ:** あるメンバーが、「新プロジェクトの仕様書を、新入社員でも読みやすいように比喩表現や行間を読ませる情緒的な文章で作成した。これをAIへのインプット（SSOT）にしよう」と提案してきました。
Agent駆動の原則に基づき、この提案に対する懸念点として**適切なもの**をすべて選んでください。（複数選択）
- [x] 人間にとっての「読みやすさ（情緒・比喩）」は、AIにとっては論理構造のパースを阻害するノイズとなりやすい。
- [x] 曖昧な表現や行間が存在すると、AIが勝手な推測（ハルシネーション）を行って仕様を誤認するリスクが高まる。
- [ ] 人間向けのドキュメントをAI用に変換するのは二度手間になるため、そのまま入力するのがベストプラクティスである。
- [ ] 読みやすい文章はAIのトークン消費量を節約できるため、むしろ推奨されるべきアプローチである。
