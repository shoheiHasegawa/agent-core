**問題数:** 全10問（理解チェック8問、応用シナリオ問題2問）

## 【基礎理解チェック：8問】

**Q1. 【単一選択（正しいもの）】**
コンテキストウィンドウ（AIが一度に読み込める情報量）に関する原則として、最も適切なものはどれですか？
- [x] 読み込める量が多くても、無関係な情報を詰め込むと精度が落ちるため、必要な情報だけを厳選して渡すべきである。
- [ ] 最新のAIは処理能力が高いため、上限に達しない限りプロジェクトの全ファイルを常に読み込ませるのがベストである。
- [ ] 情報量が少ないほどAIの想像力が働くため、コンテキストウィンドウの機能は極力使わない方がよい。
- [ ] コンテキストの量が一定を超えるとAIが自動的に古い情報を削除してくれるため、人間が情報量を管理する必要はない。

**Q2. 【単一選択（誤っているもの）】**
ファイル名による「認知的予習（ルーティング）」について、**誤っているもの**を1つ選んでください。
- [x] 整理整頓のために、ファイル名は「企画書.md」のような短い名詞や、「01_仕様.md」のような連番（プレフィックス）にするのが最も効果的である。
- [ ] ファイル名に「主張（命題）」を載せることで、人間にとってもAIにとっても内容を判別するコストを下げる効果がある。
- [ ] 曖昧なファイル名は、AIに「中身を開いて確認する」という不要な同期アクセスを強制し、推論リソースを浪費させる。
- [ ] RAG（検索）において、ファイル名自体が強力なインデックスとなり、不要なファイルの読み込み（ノイズ）を防ぐ。

**Q3. 【複数選択（適切なもの）】**
AIに「自律的に情報を探しに行かせる（ルーティング）」ための工夫として、**適切なもの**をすべて選んでください。（複数選択）
- [x] ディレクトリの階層構造や役割を記述した目次ファイル（例：`_index.md`）を用意し、AIが空間を把握できるようにする。
- [x] 各ファイルの名前を具体的にし、ファイルを開かずとも中身の性質（主張や役割）が推定できる状態にする。
- [ ] 人間がすべての必要なファイルを事前に入念に探し出し、チャット開始時にすべて手動で添付する。
- [ ] どのファイルに何があるかをAIに推測させるため、あえてファイル名をごく一般的な英単語（例：`data1.txt`）で統一する。

**Q4. 【単一選択（最も適切なもの）】**
AI環境下における「ディレクトリ分割・ファイル整理」の軸として、Agent駆動の観点から推奨される考え方はどれですか？
- [x] 人間の「目的（プロジェクトごと）」ではなく、システムの「アーキテクチャの成熟度（一時的か、永続的か）」を優先して分割する。
- [ ] AIが探しやすいように、すべてのファイルを1つの巨大なフォルダ（フラットな構造）に格納する。
- [ ] 情報の鮮度を保つため、日報のように「日付ごと」のフォルダを作成して日々の気づきを分散させる。
- [ ] ファイル数が多くなるとAIが混乱するため、複数の概念を無理にでも1つの長大なドキュメントに統合する。

**Q5. 【単一選択（誤っているもの）】**
大量の情報をAIに読み込ませた際に発生する「アテンション（注意力）の低下」を防ぐアプローチとして、**誤っているもの**を1つ選んでください。
- [x] AIが重要な指示を見落とさないよう、プロンプトの冒頭から末尾まで何度も同じ指示を繰り返し記述して強制する。
- [ ] アクティブでない過去のログや、現在使われていない不要なコードは読み込み対象から除外する。
- [ ] 広範な情報の中から、AI自身に必要なファイルだけを選択的にロード（JIT読み込み）させる仕組みを作る。
- [ ] 人間にとっての「念のためのアーカイブ」は、AIにとってはノイズになるという事実を認識し破棄・隔離する。

**Q6. 【複数選択（誤っているもの）】**
情報提供のアプローチとして、**誤っているもの（アンチパターン）**をすべて選んでください。（複数選択）
- [x] 何が役立つか分からないため、とりあえずプロジェクトに関連しそうな資料をすべてドラッグ＆ドロップでAIに渡す。
- [x] 視認性を高めるため、ファイル名は「A案.md」「B案.md」と短くし、詳細はファイル内に全て記述する運用にする。
- [ ] AIが必要な時に必要な情報だけをピンポイントで取得できるよう、インデックス（目次）を整備して案内する。
- [ ] 過去の検証でボツになった案のファイルは、現在の検討のノイズになるためAIの読み込みスコープから外す。

**Q7. 【単一選択（正しいもの）】**
「ファイル名はUI（ユーザーインターフェース）である」という原則が意味するところはどれですか？
- [x] ファイル名自体が、中身を読む前に「このファイルを読むべきか」を人間とAIに判断させるための重要なインターフェースとして機能するということ。
- [ ] ユーザーの好みに合わせて、ファイル名に絵文字や特殊記号を多用して視覚的に見栄え良く装飾すべきであるということ。
- [ ] ファイル名はOSの制限に縛られるため、なるべくアルファベットのみを用い、短く無機質なものに統一すべきであるということ。
- [ ] 人間が検索しやすければ十分であり、AIがそのファイル名をどう認識するかを考慮する必要はないということ。

**Q8. 【単一選択（最も適切なもの）】**
あるリポジトリに数百のMarkdownファイルが存在します。AIに特定のテーマについてのまとめを作成させたい場合、最も効率的な方法はどれですか？
- [x] ルートにある `_index.md` や `README.md` を起点として渡し、AI自身に関連するファイルを探索・ロード（ルーティング）させる。
- [ ] 数百のファイルをすべてプロンプトに貼り付け、AIの高い処理能力に任せて必要な情報を抽出させる。
- [ ] 人間が数時間をかけて関連ファイルを3つ程度に絞り込み、それ以外の存在はAIに一切知らせずに作業を依頼する。
- [ ] ファイル数が多いとAIが対応できないため、すべてのファイルを1つのPDFに結合してから読み込ませる。

## 【応用シナリオ問題：2問】

**Q9. 【単一選択（最も確実な対策）】**
**シナリオ:** プロジェクトの資料が大量に蓄積されており、AIに仕様変更の相談をしたところ、AIが「最新の仕様書」と「半年前の古い議事録」の内容を混同して回答してきました。この問題を根本的に解決するためのアプローチはどれですか？
- [x] アーキテクチャの成熟度に基づき、古い議事録は「アーカイブ領域」へ物理的に隔離し、AIの探索スコープ（検索範囲）から除外する。
- [ ] AIに対して「半年前の議事録は無視して、最新の仕様書だけを見てください」と強い口調でプロンプトを入力する。
- [ ] 混同を防ぐため、古い議事録のファイル名を「(古い)議事録.md」に変更し、同じフォルダに保管し続ける。
- [ ] AIの限界だと割り切り、今後は資料を一切渡さずに人間が口頭で状況を説明しながらチャットを進める。

**Q10. 【複数選択（指摘すべき懸念点）】**
**シナリオ:** 同僚が「ファイルの整理術」として、「どんなファイルも『[日付]_[担当者]_[種類].md』という規則的な短い名前（例: 20260701_Yamada_Memo.md）にして、1つのフォルダに放り込むのが一番合理的だ」と主張しています。
Agent駆動の観点から、この運用に対する懸念点として**適切なもの**をすべて選んでください。（複数選択）
- [x] ファイル名に「主張（命題）」が含まれていないため、AIが必要なファイルを見つけ出すためにすべてのファイルを総当たりで開く羽目になり、リソースを浪費する。
- [x] 日付や担当者といった人間向けの物理的順序付けは、ベクトル検索やAIのルーティングにおいては無意味なノイズになりやすい。
- [ ] 短く規則的なファイル名はAIのトークン消費を抑えることができるため、実はAgent駆動において最も推奨される命名規則である。
- [ ] 1つのフォルダにフラットに配置することで、AIはディレクトリ階層を辿る手間が省けるため、検索精度が飛躍的に向上する。
