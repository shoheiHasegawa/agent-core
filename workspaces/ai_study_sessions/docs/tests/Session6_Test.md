## 【基礎理解チェック：8問】

**Q1. 【単一選択（正しいもの）】**
「Agent OS」と呼ばれるアーキテクチャの最大の目的はどれですか？
- [x] 人間の認知負荷（コンテキスト管理やルール徹底の労力）をシステム側にオフロードし、持続可能なAIとの協働環境を構築すること。
- [ ] 会社のすべての業務をAIに完全自動化させ、人間の従業員をゼロにするための基盤を作ること。
- [ ] 複数の言語モデル（GPT-4やClaudeなど）を同時に稼働させ、処理速度を物理的に向上させること。
- [ ] ユーザーが直感的に操作できるよう、AIの画面をすべてグラフィカルなUI（ボタン操作中心）に作り変えること。

**Q2. 【単一選択（誤っているもの）】**
Agent駆動の世界における「人間の役割」に関する考え方として、**誤っているもの**を1つ選んでください。
- [x] AIが賢くなったため、人間は詳細な設計を放棄し、プロンプトに「全部いい感じにやって」と打ち込むだけの作業者（プロンプトワーカー）になるべきだ。
- [ ] 人間は、AI同士が協働するための「空間（ディレクトリやルール）」を設計するアーキテクト（オーケストレーター）の役割を担う。
- [ ] AIの局所最適化（タスクごとの暴走）によるアーキテクチャ崩壊を防ぐため、全体を俯瞰する人間のシステム設計能力が防御壁となる。
- [ ] 人間は「タスクの細分化」と「成果物の評価（品質ゲート）」という、AIには担いきれない高次な意思決定にフォーカスする。

**Q3. 【複数選択（適切なもの）】**
タスクを細分化してAIに委譲（Delegation）する際の原則として、**適切なもの**をすべて選んでください。（複数選択）
- [x] 「どのようにやるか（How）」を細かく指示するのではなく、「どこまでやっていいか（スコープの制約）」を明確にして委譲する。
- [x] 細分化された各タスクは、可能な限り他のタスクと独立して実行・検証できる状態（疎結合）にしてからAgentに渡す。
- [ ] 効率化のため、要件定義、コーディング、テスト作成といった一連のタスクを1つの大きな指示としてまとめて一人のAgentに丸投げする。
- [ ] 委譲したタスクが失敗した場合は、AIに自律性を学ばせるため、人間は一切介入せずにAIが自力で解決するまで放置する。

**Q4. 【単一選択（最も適切なもの）】**
「コンテキストの純度」「SSOT」「ルールの分離（憲法とSKILL）」といった原則が、すべて連動することで得られる最大の相乗効果はどれですか？
- [x] ハルシネーション（情報の捏造）やルールの見落としが構造的に排除され、AIへの指示が常に「予測可能で安定した結果」を生み出すようになる。
- [ ] これらの原則をすべて守ることで、クラウド利用料やAIへのAPI課金が完全に無料になる仕組みが構築される。
- [ ] AIの学習モデル自体が進化し、人間が指示を出す前にユーザーの心を読んでタスクを完了させるようになる。
- [ ] すべてのドキュメントが人間の好む「情緒的で美しい文章」に自動変換され、職場のコミュニケーションが円滑になる。

**Q5. 【単一選択（誤っているもの）】**
これまでのセッションで学んだ内容の「アンチパターン（やってはいけないこと）」の総まとめとして、**誤っているもの**を1つ選んでください。
- [x] コンテキストの管理やルーティングは人間にとって手間なので、最終的には「すべての情報をAIに丸投げして整理させる」のが理想の姿である。
- [ ] 「念のため」と過去の履歴を残すことは、心理的安全性と引き換えにコンテキスト汚染（ハルシネーションの元凶）を引き起こす。
- [ ] 魂（普遍的ルール）と肉体（特定の手順）を統合してしまうと、AIの再利用性が失われ、変化に対応できないシステムになる。
- [ ] 実装を行ったAgentにそのまま検証（テスト）を行わせると、確証バイアスによる手抜き（Sandbagging）が発生する。

**Q6. 【複数選択（正しいもの）】**
「オーケストレーション（全体最適化）」において、複数Agentの連携を成功させるための条件として、**正しいもの**をすべて選んでください。（複数選択）
- [x] Agent間で受け渡しをする情報（SSOT）は、人間向けではなく機械可読性の高い（パース可能な）フォーマットで標準化されていること。
- [x] 各Agentの責任範囲（スコープ）と境界線が明確であり、単一責任の原則に基づいてタスクがアサインされていること。
- [ ] 連携をスムーズにするため、すべてのAgentに同じチャットスレッドを共有させ、全員が同時に発言できる環境を作ること。
- [ ] 連携途中のプロセス（検討過程のメモや一時ファイル）を永久保存し、後段のAgentすべてに読み込ませること。

**Q7. 【単一選択（正しいもの）】**
AIの評価タスクにおいて、「三位一体モデル（意思決定・仕様・テスト）」が重要とされる理由は何ですか？
- [x] これらが分離・独立して存在することで、AIが自らの作業結果を「仕様」と「テスト」に照らし合わせて客観的に自己診断（セルフチェック）できるから。
- [ ] 3つの要素を1つの長大なドキュメントにまとめることで、AIが読み込むファイルの数を減らし、トークン消費を抑えることができるから。
- [ ] 意思決定をAIが行い、仕様を人間が書き、テストを再びAIが行うという「人間とAIの交互作業」を強制するため。
- [ ] 評価タスク自体をなくし、仕様がそのまま自動的に本番環境へデプロイされる魔法のようなワークフローを実現するため。

**Q8. 【単一選択（最も適切なもの）】**

- [x] 複雑な実務作業は自律的なエージェント群に委ね、人間は「何を作るべきか（What）」の決定と「空間のアーキテクチャ設計」に集中する。
- [ ] 人間がプロンプトのテクニックを極め、「どんなAIも思い通りに操れるプロンプトエンジニアリングの達人」になること。
- [ ] エージェントの挙動を監視するため、人間が24時間体制でAIのチャットログをチェックする監視業務に専念すること。
- [ ] AIがすべてを代行するため、人間は一切の意思決定やマネジメントから解放され、思考することを完全にやめること。

## 【応用シナリオ問題：2問】

**Q9. 【単一選択（最も確実な対策）】**
**シナリオ:** あなたは大規模なプロジェクトのリーダーです。チームメンバーそれぞれが独自にAIを活用し始めましたが、「AさんのAIが作った仕様書を、BさんのAIが読み間違える」「AIごとにアウトプットの品質がバラバラ」という問題（スコープジレンマ）が発生しています。
Agent OSの観点から、このカオスを収束させるための最適なアプローチはどれですか？
- [x] プロジェクト共通の「ディレクトリ構成（空間）」と「SSOTのフォーマット（機械可読性）」を定義し、全メンバー（とAI）にその空間制約を守らせる。
- [ ] メンバー全員に「AIへの正しいプロンプトの書き方」を指導する研修を毎日実施し、個人のプロンプトスキルを底上げする。
- [ ] 問題を起こさない最も優秀なAI（例えばClaude 3.5 Sonnet）にツールを一本化し、それ以外のAIの使用を全面的に禁止する。
- [ ] AI同士の連携はまだ技術的に不可能であると判断し、AI間でデータを渡す際は必ず人間が手動で翻訳・要約するルールにする。

**Q10. 【複数選択（指摘すべき懸念点）】**
**シナリオ:** 経営層から、「うちの会社でもAgent OSを導入しよう。ついては、すべての部署の業務マニュアル、過去の意思決定ログ、日々のチャット履歴を統合した『巨大な全知全能データベース』を作り、全Agentにそれを常時接続させなさい」というトップダウンの指示がありました。
これまでのセッション（純度・SSOT・ルール分離など）の知識を総動員して、この指示に対する**クリティカルな懸念点**をすべて選んでください。（複数選択）
- [x] アクティブでない過去のログや意思決定までデータベースに含めると、コンテキストが激しく汚染され、Agentの回答にハルシネーションが頻発する。
- [x] マニュアル（How）と哲学（What/Why）が分離されず常時接続されると、Agentのアテンションが低下し、特定のタスクに集中できず品質が崩壊する。
- [ ] 全知全能データベースは情報量が多すぎるため、AIが学習を放棄し、意図的にサーバーをダウンさせる「反乱」を起こすリスクがある。
- [ ] Agent OSとはそもそも「人間がプロンプトを打つ手間をなくすだけのツール」であるため、経営層が考えるような高度な業務自動化には使えない。
