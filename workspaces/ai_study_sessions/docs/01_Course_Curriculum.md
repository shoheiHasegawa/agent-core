# AI活用勉強会 カリキュラム定義書（オンデマンド版）

本ドキュメントは、全7回（Session 0〜6）のオンデマンド教材の提供内容と、受講者の学習体験（UX）を定義したSSOT（正本）です。

## 🎓 全体目標（基礎編のゴール）
受講者が「AIにお願いする（プロンプト・エンジニアリング）」という発想から脱却し、「情報の粒度を整え、必要な場所へ誘導し、役割と手順を切り分ける」ことでAIを統制する**「オーケストレーター」**になること。

---

## Session 0: 「Agent駆動」の思想と、魔法の箱（Obsidian）の準備

- **🎯 ゴール**: プロンプト疲れから解放される「Agent駆動」の未来像を共有し、ローカル環境（Obsidian）とシステム設定（憲法）の準備を完了する。
- **🔥 動機づけ（絶望の提示）**: 「毎回AIに『あなたはプロです。日本語で答えて』と入力するの、疲れませんか？」という認知負荷の痛みを提示。
- **📦 提供教材**: `session_0/README.md`
- **💻 セルフワーク**: Obsidianのインストール、BYO-AI環境別「システム設定対応表」の確認。
- **✅ 検証と定着（ルーブリック）**:
  - 【合格基準】自身の使っているAI環境において、どこに「システム設定（憲法）」を入力すればよいか（読み替え方）を理解している。

---

## Session 1: コンテキストの「純度」とGIGOの原則

- **🎯 ゴール**: AIの出力品質は「プロンプト」ではなく「入力情報の純度」に依存することを理解する。
- **🔥 動機づけ（絶望の提示）**: 「AIがもっともらしい嘘（ハルシネーション）をついて、使い物にならなかった経験はありませんか？」
- **📦 提供教材**: `session_1/README.md`, `sandbox/`（議事録とチャットログが混ざったカオスなファイル、純度の高い要件定義書）
- **💻 セルフワーク**: カオスなファイルと綺麗なファイルをAIに読み込ませ、出力（品質）の劇的な差を体験する。
- **✅ 検証と定着（ルーブリック）**:
  - 【合格基準】AIの知能不足ではなく「人間の入力ノイズ」が嘘を引き起こすと説明できる。1タスク1セッションの原則（定期的な履歴リセット）を実行できる。

---

## Session 2: 「SSOT（Single Source of Truth）」と壁打ち

- **🎯 ゴール**: 常に正本（SSOT）を維持し、AIの「推測（勝手な穴埋め）」をシステム的に排除する。
- **🔥 動機づけ（絶望の提示）**: 「AIにコードや文章を書かせたら、なんか全然違う（けど修正を指示するのも面倒くさい）となったことはありませんか？」
- **📦 提供教材**: `session_2/README.md`, `sandbox/`（情報の更新が散らばった複数ファイル、一元管理されたSSOTファイル）
- **💻 セルフワーク**: AIを「作業者」としてではなく、「壁打ち相手（要件の引き出し役）」として使い、認識をすり合わせた上でSSOTを明文化する体験。
- **✅ 検証と定着（ルーブリック）**:
  - 【合格基準】AIに推測で書かせるのではなく、事前の壁打ちで考慮漏れを潰してからSSOTを更新するフローを実践できる。

---

## Session 3: コンテキストの「量」とルーティング

- **🎯 ゴール**: 情報量が増えた際に、AIが迷子にならないよう「目次（_index.md）」を使って誘導（ルーティング）する。
- **🔥 動機づけ（絶望の提示）**: 「プロジェクトの資料を全部AIに読み込ませたら、AIが混乱してアテンション（注意力）が吹き飛んだことはありませんか？」
- **📦 提供教材**: `session_3/README.md`, `sandbox/`（大量の無秩序なファイル群、構造化された `_index.md`）
- **💻 セルフワーク**: AIに `_index.md` を読ませて、必要なファイルだけを自己解決的に探させる（ルーティングさせる）実験。
- **✅ 検証と定着（ルーブリック）**:
  - 【合格基準】人間がすべてのファイルを探してAIに渡すのではなく、AI自身に目次を読ませて「情報を取りに行かせる」空間設計ができる。

---

## Session 4: 絶対的な制約としての「憲法（ルール）」

- **🎯 ゴール**: 毎回指示（How）を出すのではなく、事前設定した「制約（What not to do）」でAIの振る舞いを自動統制する。
- **🔥 動機づけ（絶望の提示）**: 「たまにAIが英語で答えてきたり、余計なおしゃべり（ノイズ）を入れてきたりしてイライラしませんか？」
- **📦 提供教材**: `session_4/README.md`, `sandbox/`（憲法ファイル）
- **💻 セルフワーク**: 「日本語で、箇条書きで、推測せず逆質問せよ」という憲法をシステムにロードさせ、適当な指示を出してもAIが暴走せずクールに逆質問してくる挙動を体験する。
- **✅ 検証と定着（ルーブリック）**:
  - 【合格基準】プロンプトエンジニアリングを捨て、システム設定（憲法）によってグローバルルールを担保できる。

---

## Session 5: 「魂（役割）」と「肉体（手順/SKILL）」の分離

- **🎯 ゴール**: 憲法にすべてのマニュアルを詰め込むとアテンションが破綻することを学び、「役割」と「手順（SKILL）」を物理的に分離する。
- **🔥 動機づけ（絶望の提示）**: 「AIに色々なルールを教え込んだら、議事録を頼んだのにコードレビューのルールを適用してきたりと、AIがポンコツ化した経験はありませんか？」
- **📦 提供教材**: `session_5/README.md`, `sandbox/`（肥大化した最悪のルールファイル、分離されたSKILLフォルダ構造）
- **💻 セルフワーク**: 肥大化したマニュアルを解体し、「いつでも守る憲法」と「特定作業用のSKILL」のフォルダに分割・整理するリファクタリング作業。
- **✅ 検証と定着（ルーブリック）**:
  - 【合格基準】AIに渡すルールを「必要な時だけロード（JIT読み込み）する」という職務分離のアーキテクチャを構築できる。

---

## Session 6: You_Inc Agent OS 全体像とオーケストレーション

- **🎯 ゴール**: これまでの知識を統合し、「データ（Vault）」「憲法（役割）」「手順（SKILL）」が連動する Agent OS の全体像を俯瞰する。
- **🔥 動機づけ（絶望の提示）**: 「これらを手動で全部管理するのは、結局人間の認知負荷が高すぎませんか？（スコープジレンマの提示）」
- **📦 提供教材**: `session_6/README.md`（総合まとめと最終課題）
- **💻 セルフワーク**: 自分が手動で行ってきた「コンテキスト管理」を、複数のAI（全体を見るAIと局所を見るAI）に委譲する「マルチエージェント構造」の未来（応用編への架け橋）を想像する。
- **✅ 検証と定着（ルーブリック）**:
  - 【合格基準】純度、量、ルーティング、憲法、SKILL分離のすべての意味を構造的に説明でき、オーケストレーターとして振る舞うことができる。
