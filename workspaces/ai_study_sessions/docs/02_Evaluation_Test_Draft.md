# AI活用勉強会 テスト問題設計方針（Evaluation Design Policy）

本ドキュメントは、AI活用勉強会（Session 1〜6）において、各セッション10問（合計60問）のテスト問題を作成するための基本方針、押さえるべきポイント、および受講者が誤解しやすいアンチパターンをまとめたものです。

## 🎯 全体方針
- **問題構成**: 各セッションにつき10問（理解チェック8問、応用シナリオ問題2問）
- **出題形式**: 自動採点可能な選択式（単一選択・複数選択、正しいもの・誤っているもの探し）
- **評価の軸**: 知識の丸暗記ではなく、「なぜそのルールが必要なのか（絶望の回避）」と「具体的なAgent駆動の行動がとれるか」を問う。特に、**人間にとっての正解（心理的安全性・読みやすさ）が、AIにとってはアンチパターンになる**という捻りのある問題を用意する。

---

## Session 1: コンテキストの「純度」とGIGOの原則
- **✅ 押さえてほしいポイント**: 
  - ハルシネーション（AIの嘘）はAIの知能不足ではなく、人間の入力する「コンテキストのノイズ（不純物）」が原因であること。
  - 「1タスク1セッション」の徹底（タスクが変わればチャット履歴をリセットする）。
- **⚠️ 捻りのあるアンチパターン（誤答の選択肢）**: 
  - 「AIのモデル（GPT-4等）が進化すれば、文脈管理やプロンプトは不要になる」
  - 「同じチャットスレッドを長く使い続ける方が、AIが文脈を学習してくれて賢くなる」
  - 💎 **「念のため、過去の履歴や背景のアーカイブもすべてAIに渡しておいた方が親切である」**（実際はこれがコンテキスト汚染の元凶となる）

## Session 2: 「SSOT（正本）」と壁打ち
- **✅ 押さえてほしいポイント**: 
  - AIに「推測（勝手な穴埋め）」をさせないための「壁打ち」の重要性。
  - 壁打ちを通じて要件を固め、唯一の情報源（SSOT）に集約するフロー。
- **⚠️ 捻りのあるアンチパターン（誤答の選択肢）**: 
  - 「最初からAIに完璧な成果物（企画書やコード）をワンパンで出力させるのが、優れたAI活用である」
  - 💎 **「人間が読んで『美しい・行間が読める』ドキュメントこそが最高のSSOTである」**（実際はAIが構造的にパースできる機械可読性が正義）

## Session 3: コンテキストの「量」とルーティング
- **✅ 押さえてほしいポイント**: 
  - コンテキストウィンドウが広くても、全情報を詰め込むとAIの精度が落ちる（必要な情報だけを渡す重要性）。
  - 人間がすべてを探すのではなく、`_index.md` などの目次を使ってAI自身に「情報を取りに行かせる（ルーティングさせる）」。
- **⚠️ 捻りのあるアンチパターン（誤答の選択肢）**: 
  - 「とりあえずプロジェクトの全ファイルを全部AIに投げ込めば、AIが勝手に要約して答えてくれる」
  - 💎 **「整理のために、ファイル名は『企画書.md』のような短い名詞や番号（プレフィックス）にするのがよい」**（実際はファイル名に「命題・主張」を載せないと、AIが中身を判別できずに不要なファイルを開いてしまいノイズになる）

## Session 4: 絶対的な制約としての「憲法（ルール）」
- **✅ 押さえてほしいポイント**: 
  - 毎回プロンプトで「How（どうやるか）」を指示するのではなく、システム設定に「What not to do（やってはいけないこと＝憲法）」を登録し、グローバルルールとして自動統制する。
- **⚠️ 捻りのあるアンチパターン（誤答の選択肢）**: 
  - 「毎回のプロンプトの最後に『必ず日本語で答えて』と書くのが丁寧な使い方だ」
  - 「憲法にすべての作業手順（マニュアル）を詰め込めばAIが万能になる」
  - 💎 **「AIにはルールを毎回考えさせながら柔軟に対応させた方がよい」**（実際は、静的な構成定義をハードコードして注入し、メタな推論リソースを浪費させないのが正解）

## Session 5: 「魂（役割）」と「肉体（手順/SKILL）」の分離
- **✅ 押さえてほしいポイント**: 
  - 憲法の肥大化によるアテンション崩壊を防ぐため、常に守るべき「憲法」と、特定作業時のみ読み込ませる「SKILL（手順）」を分離する（必要な時だけのJIT読み込み）。
- **⚠️ 捻りのあるアンチパターン（誤答の選択肢）**: 
  - 「マニュアルは1つの巨大なファイルに全部まとまっている方が、AIにとっても人間にとっても便利だ」
  - 💎 **「特定の作業が得意なAIを作るには、プロンプトと手順をガチガチに結合した専用チャットボットを作るべきだ」**（魂と肉体を結合すると汎用性が死ぬ。「魂」は軽い思考基盤とし、必要な時だけ「重い肉体」を読み込ませるのが正解）

## Session 6: You_Inc Agent OS 全体像とオーケストレーション
- **✅ 押さえてほしいポイント**: 
  - 純度・SSOT・量・憲法・SKILL分離がすべて連動し、人間の認知負荷を下げる「Agent OS」のアーキテクチャ。
  - 人間は「プロンプトを打つ作業者」ではなく、「空間の設計者（オーケストレーター）」であること。
- **⚠️ 捻りのあるアンチパターン（誤答の選択肢）**: 
  - 「結局、コンテキストの管理はすべて人間が手作業で行わなければならない」
  - 💎 **「実装や文章を書いたAIに、そのまま自分が書いたコード（文章）をレビュー・テストさせれば文脈を分かっていて効率的である」**（実際は「自分が正しい」という確証バイアスで汚染されているため、手抜き（Sandbagging）が発生する。実装と検証はペルソナを物理分離しなければならない）
