## 監査軸1：【教育工学・認知負荷の監査（ID / IS観点）】

### 1.1 Good Points（高く評価できる設計）
- **チャンク化と構造提示（`03_IS.md` 3-2 準拠）**: 第7章を「部屋と鍵・ガードレール・権限・キーホルダー」、第8章を「家具（表）・5人の番犬（制約）・目次（INDEX）・覗き窓（VIEW）・引っ越し（データ移動）」という一貫した「セキュリティマンションの比喩体系」で統合しており、断片知識ではなく構造化されたスキーマとして記憶に残る設計になっている。

### 1.2 Critical Issues（重大な課題・認知負荷のボトルネック）

#### 🚨 [ID-1] 25分（1トピック5分）に対する情報過多と「幹／枝葉（`> 📝 補足`）」の未分離
`03_IS.md`（演習②「5分でわかる〇〇」）の通り、5分間で初学者に伝達・腹落ちさせられる概念は**「1トピックにつき1つのコア概念（幹）」**が限界である。しかし、以下の4トピックは1つの5分枠の中に複数の重い概念や試験外の周辺知識（枝葉）が同居しており、このままスライド化すると説明が駆け足になり消化不良（認知パンク）を起こす。
1. **Topic 2（`SYS` vs `SYSTEM` と `SYSDBA`）**:
   - Mermaid図（L146）および本文（L158）に `SYSOPER`, `SYSBACKUP`, `SYSDG`, `SYSKM` まで列挙されている。これらは全20問のどこでも問われない12c以降の職務分掌権限であり、初学者が5分で聞くにはノイズになる（幹はあくまで「`SYS`（データディクショナリ所有・起動停止可・`AS SYSDBA`必須）vs `SYSTEM`（日常管理・起動停止不可）」の対比）。
2. **Topic 3（アカウント状態 ＋ `QUOTA` ＋ `PROFILE`）**:
   - 5分間に「①ロック/期限切れ」「②表領域クォータ（＋`ORA-01950`＋一時表領域の例外）」「③プロファイル（パスワード制限＋CPUリソース制限＋省略時`DEFAULT`）」の**3大機能＋4大鉄則**が詰め込まれている。特にL207の「`QUOTA`が0だとデータを1件入れた瞬間に`ORA-01950`になる（※遅延セグメント作成による挙動）」は、なぜ`CREATE TABLE`時ではなく`INSERT`時なのかという疑問を誘発しやすく、口頭説明が長引く要因になる。
3. **Topic 5（ロール `Role` ＋ 権限委譲オプション `WITH ADMIN/GRANT OPTION`）**:
   - **前半座学で最も認知負荷が高い最難関トピック**。「ロールの仕様（システム権限・オブジェクト権限・ロールのネスト可、プロファイルへの付与不可）」と、「委譲オプションの剥奪（`REVOKE`）時の非対称な連鎖挙動（システム権限は連鎖しない vs オブジェクト権限は連鎖する）」という**2つの独立した重いテーマ**が5分枠に入っている。さらにHOW（L292-296）で事前定義ロール4種（`DBA`, `CONNECT`, `RESOURCE`, `SELECT_CATALOG_ROLE`）まで解説しようとしており、確実に5分を超過する。
4. **Topic 1 & Topic 6（非スキーマオブジェクト、および `SEQUENCE` / `SYNONYM`）**:
   - Topic 1（L115）の「非スキーマ・オブジェクト（表領域、ユーザー、ロール、ディレクトリ）」や、Topic 6（L331, L339-340）の「順序（`SEQUENCE`）」「シノニム（`SYNONYM`）」は、今回の練習問題20問にもハンズオンにも登場しない。全体マップとして名前を見せるのは良いが、スライド本編で同列の重みで解説すると「表（`TABLE`）とデータ型（`VARCHAR2` vs `CHAR`）」への集中が削がれる。

#### 🚨 [ID-2] パイクの「90/20/8の法則」における「90分に1度の休憩」の欠落とクイズ解説時間の逼迫
- **休憩時間の不在**: `03_IS.md`（L250）が定めるパイクの法則では「**90分に1度休憩する**」ことが必須原則だが、120分タイムライン（L41-62）には**休憩（Break）が1分も設定されていない**。75分連続で座学2本＋クイズ2本を走った直後に休憩なしで25分の実機ハンズオンと20分の総仕上げクイズ（10問）に突入すると、後半の集中力が著しく低下する。
- **クイズ10分枠（回答5分＋解説5分）の時間不足**: 各クイズ枠（10分）で長文シナリオ問題5問を回答させ、さらに全選択肢（a〜d）のNG理由まで口頭で解説するには、1問あたり回答1分＋解説1分しかない。講師が全選択肢を口頭で読み上げると確実に時間超過する。

#### ⚠️ [ID-3] スリー・ソー導入の論理ジャンプ（Topic 3）と比喩の揺れ（Topic 10）
- **Topic 3 のスリー・ソー（L165-167）**: 「そうだよね（仮パスワード変更と退職者ロック）」から「そういえば（新入社員がテストデータを無限に作ったらディスクがパンクする）」へ、話題が「認証セキュリティ」から「ディスク容量管理」へ唐突にジャンプしており、文脈の繋がりにやや無理がある。
- **Topic 10 の比喩の不一致（L522 vs L529）**: `SQL*Loader` の比喩が、スリー・ソー（L522）では「一括投入する**掃除機**」となっているのに、直後のWHAT（L529）では「鍋に流し込む**フードプロセッサー**」に変わっており、1トピック内で比喩がブレている。
- **Topic 5 の用語暗記補助の不足**: 「のれん分け vs 合鍵の又貸し」の比喩は秀逸だが、初学者が試験で最も間違えるのは「**どっちが `ADMIN` でどっちが `GRANT` だっけ？**」という英単語と対象の紐付けである。

#### ⚠️ [ID-4] 行動目標（Learning Objectives）の記述粒度（`02_ID.md` 2-3 基準）
- `02_ID.md`（L48-50）では「一つの文章に一つの目標を設定する」「評価される条件・基準を明示する」と定められているが、`design_blueprint.md` の認知領域目標（L20-25）は1文の中に3〜4個の要素と複数の動詞（「説明でき、〜特定できる」等）が詰め込まれている。

### 1.3 Improvement Proposals（教育工学面の改善提案）
1. **各スライドにおける「幹（本編）」と「`> 📝 補足`（枝葉）」の明確な視覚分離**:

## 監査軸3：【ハンズオン「本日の総まとめ実験」のOracle 26ai Free 実機技術監査】

`Oracle-ai_instal.md` の構築手順（AWS EC2 Amazon Linux 2023 + Oracle AI Database 26ai Free `23.26.0.0.0`、CDB=`FREE`、PDB=`FREEPDB1`、`bold` ユーザー、`NLS_LANG=Japanese_Japan.AL32UTF8`）に対し、実験1〜3＋おまけA・Bの全コマンドを上から順にトレース検証した結果を報告する。

### 3.1 重点検証項目の判定結果

1. **【検証①】主キー自動作成INDEXと手動 `CREATE INDEX` の列重複（`ORA-01408`）の有無**:
   - **判定：✅ 問題なし（エラーにならない）**
   - 実験1（L611-619）では、主キー（`PRIMARY KEY`）は `emp_id` 列に定義され（自動で `emp_id` 列に一意索引 `SYS_C00...` が生成される）、手動の `CREATE INDEX idx_emp_dept` は `dept_name` 列に作成されている。対象列が異なるため、`ORA-01408: この列リストにはすでに索引が作成されています` は発生せず正常に作成される。
2. **【検証②】`DROP TABLE` 実行直後の `user_objects.status` と `SELECT` 時の `ORA-04063` 挙動**:
   - **判定：✅ 正確（実機挙動と一致）**
   - Oracleのオブジェクト依存性管理（`DEPENDENCY$`）により、参照先の親表 `emp_secret` が `DROP TABLE` された瞬間に（まだ一度もビューを `SELECT` や再コンパイルしていなくても）、`user_objects` 内の `V_EMP_PUBLIC` の `STATUS` 列は即座に `VALID` から **`INVALID`** に遷移する。また、直後の `SELECT * FROM v_emp_public;` で自動再コンパイルが走って失敗し、確実に **`ORA-04063`** が発生する。なお、`DROP TABLE emp_secret;`（`PURGE` なし）でもリサイクルビン移動に伴い `user_indexes` からは `EMP_SECRET` 名義の行が消え、`user_objects` の `IN ('EMP_SECRET', 'IDX_EMP_DEPT', 'V_EMP_PUBLIC')` でも `V_EMP_PUBLIC` のみが `INVALID` で残るため、期待出力通りとなる。

### 3.2 検出された実機技術バグ・環境乖離（Must Fix / Should Fix）

#### 🚨 [TECH-1]【致命的バグ】おまけ実験B：`Data Pump (expdp/impdp)` における PDB (`freepdb1`) の `DIRECTORY=DATA_PUMP_DIR` エラー（`ORA-39002` / `ORA-39070`）
- **現象**: おまけ実験B（L892, L903）では `DIRECTORY=DATA_PUMP_DIR` を指定して `expdp bold/bold@freepdb1 ...` を実行している。しかし、Oracle Multitenant（CDB/PDB構成）のPDB（`freepdb1`）では、デフォルトの `DATA_PUMP_DIR` のOSパスが `/opt/oracle/admin/FREE/dpdump/<PDBのGUID>/` にマッピングされており、**RPMインストール直後の環境ではこの `<PDBのGUID>` サブディレクトリがOS上に物理作成されていないケースがある**（あるいは権限・パスの確認が必要になる）。OS上にディレクトリが存在しないと、`expdp` 実行時に以下のエラーで即死する：
  ```text
  ORA-39002: 操作が無効です
  ORA-39070: ログ・ファイルをオープンできません。
  ORA-29283: ファイル操作が無効です
  ```
- **修正案（100%確実に動く自己完結コード）**:
  `bold` ユーザーは `DBA` ロール（`CREATE ANY DIRECTORY` 権限を含む）を持っているため、おまけBのStep 1で確実に存在する `/tmp` を指すディレクトリオブジェクト `dp_dir` を自ら作成してから `expdp` / `impdp` を実行する。これにより **100%エラーを回避できるだけでなく、Topic 10の図解にある「DIRECTORYオブジェクト」の作成と、OS上の `/tmp/load_test_bk.dmp` ファイルの実在確認まで一気通貫で体験できる**。
  ```sql
  -- おまけB 事前準備：ダンプ出力先ディレクトリオブジェクトを /tmp に作成
  CREATE OR REPLACE DIRECTORY dp_dir AS '/tmp';
  ```
  （※コマンド側は `DIRECTORY=dp_dir` に変更）

#### 🚨 [TECH-2]【初学者の混乱防止】実験2 `Step 2-1` の初期化 `DROP USER` / `DROP ROLE` で初回実行時に赤いエラー（`ORA-01918` / `ORA-01919`）が出る問題
- **現象**: 実験1の `Step 1-1`（L608）には `-- 初回はエラーになっても無視してOK` と注記があるが、実験2の `Step 2-1`（L682-683）の `DROP USER u1 CASCADE;` と `DROP ROLE staff_role;` には何の注記もない。受講者が初めて実験2を実行した際、いきなり `ORA-01918: ユーザー'U1'は存在しません` と `ORA-01919: ロール'STAFF_ROLE'は存在しません` のエラーが2連発で表示され、「直後の `Step 2-2` で見るべき本来のエラー（`ORA-01045`）」と混同してパニックになる。
- **修正案（Oracle 26ai / 23ai 新構文 `IF EXISTS` の活用）**:
  実機は **Oracle AI Database 26ai Free (`23.26.0.0.0`)** であるため、23ai以降で導入された **`DROP ... IF EXISTS` 構文**がネイティブに使用可能である！
  - `DROP TABLE IF EXISTS emp_secret CASCADE CONSTRAINTS;`（Step 1-1）
  - `DROP USER IF EXISTS u1 CASCADE;`（Step 2-1）
  - `DROP ROLE IF EXISTS staff_role;`（Step 2-1）
  - `DROP TABLE IF EXISTS load_test;`（おまけA Step 1）
  これに書き換えるだけで、初回実行時も2回目以降の再実行時も**不要なエラーが一切出なくなり、受講者は「意図した壁（エラー）だけ」を純粋に目撃できる**。

#### ⚠️ [TECH-3]【実機出力との言語乖離】`Oracle-ai_instal.md` の環境設定（`NLS_LANG=Japanese_Japan.AL32UTF8`）と英語ターミナル出力の不一致、および26aiでの `ORA-00942` メッセージ進化
- **現象**:
  1. `Oracle-ai_instal.md`（L149, L205）で `.bash_profile` に `export NLS_LANG=Japanese_Japan.AL32UTF8` が設定されているため、受講者の実機ターミナルでは SQL*Plus の出力やエラーメッセージはすべて**日本語**（例：`ユーザーは"BOLD"です。`、`レコードが選択されませんでした。`、`ORA-01045: ユーザーU1にはCREATE SESSION権限がありません。ログオンが拒否されました`）で表示される。しかし `design_blueprint.md` の「期待される出力」はすべて英語出力＋カッコ書き和訳になっている。
  2. さらに、**Oracle 23ai / 26ai（23.6以降）では `ORA-00942` のエラーメッセージが改善され、存在しない（または権限のない）スキーマ名・表名がメッセージ内に直接表示される仕様に進化している**：
     - 19c以前：`ORA-00942: 表またはビューが存在しません。` (`table or view does not exist`)
     - **26ai Free実機**：`ORA-00942: 表またはビュー"BOLD"."EMP_SECRET"が存在しません。` (`table or view "BOLD"."EMP_SECRET" does not exist`)
- **修正案**:
  「期待される出力」を実機の `NLS_LANG=Japanese_Japan.AL32UTF8` に合わせた日本語表示（または日本語メイン＋英語併記）に統一し、`ORA-00942` も26ai実機出力に合わせて `"BOLD"."EMP_SECRET"` 入りの表記にアップデートする。

#### ⚠️ [TECH-4] ローカルネーミング（`@freepdb1`）未設定環境へのフォールバック注記
- **現象**: `sqlplus bold/bold@freepdb1` や `CONN u1/benkyokai@freepdb1` は、第2回ハンズオン（`Oracle-ai_instal.md` 5-2）で `tnsnames.ora` に `FREEPDB1` エイリアスが正しく追記されていることを前提としている。万が一第2回を欠席・設定漏れしていた受講者がいる場合、`ORA-12154: TNS: 指定された接続識別子を解決できませんでした` で最初から躓く。
