2. 講師から受講生へのメッセージ

「世間で囁かれる『ジュニア不要論』を知っていますか？」

これまでの現場は「シニアが設計し、ジュニアが実装する」ことで回っていました。しかし今や、実装やコード生成はAIが一瞬でやってくれます。現場が求めているのは、指示通りにコードを書く作業者ではなく「AIの仕事をレビュー（検収）できる人」です。もしAIの出力をレビューできないなら、現場にとってジュニアの存在意義とは何でしょうか？

私自身、皆さんと同じIT歴3〜4年の現場リーダーとして、日々AIを使い倒す中で「単にコードを書くスキルではなく、裏側の構造（WHY）を理解し、AIに適切な問いを立て、その出力を設計レベルで検証する力こそが唯一の生存戦略だ」と確信しました。従来の暗記講座をすべて捨て、『DBの本質から学び、設計レビュー実践までを通して体験できる講座』を用意しました。AIに作業を丸呑みさせられる側ではなく、AIを優秀な部下として自信を持って率いるエンジニアへ、一緒に駆け上がりましょう！

3. 研修の目的

本研修の目的は、AIがコードを生成する時代において、受講生がシステムの全体構造を理解し、「AIの成果物のリスクを見抜き、現場で設計レビューができる自立したエンジニア」へと成長することです。

  1. 構造の理解（WHY）: 表面的な構文ではなく、データ整合性と性能を支える内部アーキテクチャを理解する姿勢。
  2. 問いを立てる力: AIに対して適切な前提条件やレビュー観点を提示できるプロンプト・要件定義力。
  3. 出力を検証する力: AIが生成したテーブル定義やSQLに対し、見落とされたトレードオフや現場リスクを指摘・修正できるレビュー力。

4. 研修で探求すべき中心の問い（Essential Question）

『AIがコードを書く時代、私たちはシステムの何を信じ、何を疑うべきか？』

5. 学習目標（Learning Outcomes）

  • 目標Ⅰ【本質の理解】: DBが担保すべき本質（ACID特性等）と、それを実現する内部構造（WAL、REDO/UNDO、ロック等）の仕組みを自分の言葉で平易に説明できる。
  • 目標Ⅱ【アプリ⇄インフラ両利き】: クエリやトランザクションの書き方（アプリ視点）が、メモリ・I/O・ロック競合（インフラ視点）に与える影響を論理的に指摘できる。
  • 目標Ⅲ【現場トラブルの解決】: 「画面白画面」「デッドロック」「月末バッチ遅延」などの現場あるあるトラブルの根本原因と解決策を選択できる。
  • 目標Ⅳ【AIレビュー実践】: AIが提示したテーブル設計やSQLに対し、見落とされたトレードオフ（局所最適の罠）を見抜き、設計レビューコメントを具体的に提示できる。

6. 研修の大きな特徴（教育工学に基づく設計）

  1. 学習理論に基づく授業設計（ITOR学習モデル）: インプット（解説）、スループット（思考ミニ問い）、アウトプット（模擬レビュー会議）、リフレクション（気づきの振り返り）の知のサイクルを120分内で完結。
  2. ピアラーニング（Think-Pair-Share）: 個人メモ（Think）➔ グループ議論（Pair/Share）➔ 実機実証により、他者との照合で盲点への気づきを最大化。
  3. 成人学習論に基づくタイパ最大化: 業務後の受講生に配慮し、事前課題・宿題は一切なし。平日の120分に集中して学習を完結。
  4. クラウド実機環境提供: Oracle 26ai検証環境は講師側がクラウド上に整備し、端末依存のエラーや脱落を防止。

9. 受講ルール・教材・生成AIポリシー

  • 教材: 指定の資格本購入は不要。講義スライドおよび復習用サマリーを毎回配布。
  • 実機: クラウド上のOracle 26ai環境を講師側で提供（受講生PCへのインストール不要）。
  • 生成AIポリシー: 大歓迎・推奨。講義内のレビュー演習や現場業務でAI（ChatGPT, Claude, Cursor等）を積極的に使い、学んだレビュー観点をAIにぶつける実践を推奨。
