# Lessons Learned: Oracle Course Renewal

## 🧠 学びと反省（Failure Patterns & Insights）
- **前任者資料の監査知見**: 単なる資格試験の丸暗記講義ではなく、実務に生きる普遍的な「RDBMS基礎体力（インフラ視点＋開発視点）」をインストールする講義設計とSOLID問題設計が受講者のエンゲージメントを高める。
- **NotebookLM分割投入規格**: 長大なMarkdownを一括投入するとハルシネーションを起こすため、フレーム、チャプター別、プロンプトの3分割で投入するサンドイッチ方式が極めて安定する。
- **GAS自動生成**: Google Formsの手作業作成を排除し、MarkdownからPythonスクリプトでGASを生成・流し込むことで、問題修正時の手戻りコストが激減した。
- **リブランディングにおける「しっくり感（WHYの純度）」の重要性**: 社内勉強会の名称やメッセージをロジックで綺麗に組み立てても、講師自身（社長）が現場で受講生と対峙する際の「魂の乗り方（しっくり感）」に違和感がある場合は、立ち止まって根本のコンセプトから再壁打ちする勇気が不可欠である。焦って提出用の文面をFIXさせず、WHYの解像度を極限まで高めることが最高峰の講座を生む。
- **教育コンテンツのマーケティング・集客インサイト（顧客心理とストーリーテリング）**:
  - **Feature（仕様）ではなくTransformation（理想の未来）を売る**: 顧客が欲しいのは「DBの知識（ドリル）」ではなく、「AIの出力をレビューできて現場で一目置かれる自分（穴）」。
  - **インフォメーション・ギャップによる不足の自覚化**: 「知ってる？知らない？」の問い（画面系とバッチの違い、N+1問題等）を投げかけることで、受講生は自発的に知識の穴を自覚し、納得感を持って受講を決意する。
  - **タブー（不都合な真実）からのストーリーテリング**: 「AI時代に何を学ぶか」という陳腐な綺麗事ではなく、「ジュニア不要論を知っていますか？」という直球の危機感から入り、「だからこそ現場で絶対に必要だと確信した講座を用意しました」と希望に着地させることで、熱狂的な信頼が生まれる。
  - **パラメータ（レーダーチャート）の特化と高低差の美学**: すべてが平均的に高い「器用貧乏な六角形」は誰にも刺さらない。「資格取得: 2」「応用: 2」とあえて低く抑えることで、「暗記をやらせない現場特化」のメッセージが際立つ。さらに「開発系: 4」と「基盤系: 4」を同じ高さで並べることで、「アプリの都合で決まるインフラ」と「インフラの制約で決まるアプリ」の【双方向の架け橋】という講座の真骨頂を視覚的に証明できる。
