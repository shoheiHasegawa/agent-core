# 02. Formatter & Parsing Logic (入力・解析仕様)

本仕様書は、iPhoneからのフリーテキスト入力をAgentが回収し、適切にパース（解析）してデータ構造化する一連のロジックを定義します。

## 1. 入力フロー (Data Ingestion)
*   **Source**: iCloud Drive上の `Mobile_Vault/Inbox/`
*   **Format**: `.md` または `.txt` (iPhoneからのフリーテキスト/音声入力/画像添付)
*   **Trigger**: Agentの夜間ジャーナリング（`night-routine` / `inbox-triage`）時、ファイルをPeek（覗き見）し、ユーザーとの壁打ちを経て選択的に回収（Process）する。

## 2. LLMによるパース要件 (Parsing Rules)
LLMを用いて、フリーテキストから以下の要素を抽出し構造化します。

### A. タスク分類 (Category)
*   **`[M] Must`**: 期限や絶対的な義務が伴うタスク（例: 支払い、会議、チケット予約）。
*   **`[S] Should`**: 期限はないが、自身の未来や目標（Areas）への投資となるタスク（例: 資格勉強、読書、筋トレ）。
*   **`[W] Want`**: 純粋な余暇、リフレッシュ、やりたいこと（例: ギター、温泉リサーチ、ゲーム）。

### B. 推定所要時間 (Duration)
*   テキスト内に明示的な時間（「30分で」など）があればそれを採用。
*   なければ、タスクの性質からLLMが妥当な時間（15分、30分、60分、120分など）を自動推定する。

### C. コンテキストの分離
*   タスク本体と、補足情報（「〜について調べる」「〜の参考リンク」など）を分離する。
*   アイデアメモの場合はZettelkastenノート（`00_Inbox/`）として独立保存する。

## 3. 出力フォーマット (Output Generation)
パースされたタスクは、日次パイプライン（`generate_daily_briefing.py`）により、ブリーフィングファイル（`Dashboard/Briefing_YYYY-MM-DD.md`）へ以下のMarkdownフォーマットで出力されます。
これにより、ユーザーはチェックボックスと実績枠を用いた「摩擦ゼロの実績報告（Super-loose Parser対応）」が可能となります。

```markdown
# Daily Action Plan (2026-08-03)

### 本日のタスクリスト
- [ ] [M] 住民税の支払い (予定: 15分) <!-- id: 1 -->
- [ ] [S] 応用情報の過去問 (予定: 120分) <!-- id: 2 -->
    前回メモ: データベース領域を中心に復習すること。
- [ ] 👑 [W] 週末の温泉リサーチ (予定: 30分) <!-- id: 3 -->
```
