# You_Inc アーキテクチャ移行プロジェクト：基本作業方針（Agentic Loop Workflow）

本プロジェクト（Fat Orchestration から Thin Orchestration / PubSub への移行）を通じて、システム破壊やコンテキストの濁りを防ぐため、すべての作業は以下の**「5ステップのAgentic Loop Workflow」**を遵守して進行する。

## 1. Discovery / Draft (ドラフト作成)
* メインAgent（オーケストレーター）が単独でコードやドキュメントを書き始めることは禁止する。
* 必ず、単一の専門性を持った「Draftsman」サブエージェントを起動し、初期ドラフトを作成させる。

## 2. Peer Review (ピアレビュー)
* 出来上がったドラフトに対し、別の視点を持つ「Reviewer」サブエージェントを複数起動し、批判的レビュー（Critique）を行わせる。
* 例：セキュリティ監査、UX（認知負荷）監査、移行リスク監査など。

## 3. Synthesis (統合と精緻化)
* メインAgentは各サブエージェントからのドラフトとレビュー結果を受け取り、それらを一つの成果物（Artifact/ドキュメント）として統合・精緻化する。

## 4. User Gate (人間の承認)
* 品質が担保された状態（Artifact）で必ずユーザーに提示し、合意（Proceed）を得る。
* ユーザーの承認なしに次のステップ（特にコードの破壊的変更）へ進むことを固く禁じる。

## 5. Implementation (安全な実装)
* 実装段階においても、メインAgentが一気にファイルを書き換えるのではなく、「Coder」サブエージェントに実装を委譲し、「Tester」サブエージェントに検証（Quality Gate）を通過させる。
