# Agentic OS 理想のシステムアーキテクチャ (To-Be State)

Agentic OS (`agent-core` 及び関連エコシステム) における究極の理想形（To-Be）は、「ユーザー（社長）の抽象的意図を解釈し、認知負荷ゼロでタスクを完遂する自律的かつ自己進化型の秘書エコシステム」です。各ドキュメントから抽出された構造的ルールと設計思想に基づく、完全に実現された理想のシステムアーキテクチャ像を以下に定義します。

## 1. コアパラダイム: The Secretary Paradigm と Zero-Friction Orchestration
*   **自律型秘書としての完全な委譲**: 人間がタスクリストを直接管理するパラダイムから脱却。人間は「大局的な方針（Areas）」と「未加工のアイデア（Inbox）」のみを提供し、OS（agent-core）がそれらを日次のスケジュールやバックグラウンド処理へと自動翻訳・投機的実行します。
*   **2-Tier Architectureによる摩擦ゼロのオーケストレーション**:
    *   **Tier 1 (Orchestrator)**: フロー制御とルーティングに専念する司令塔。役割（帽子）を動的に切り替えながら人間との対話をファシリテートし、バックグラウンド処理はサブエージェントへ委譲します。
    *   **Tier 2 (Worker)**: 単一責任原則（SRP）に従い、極めて専門的でスコープの限定された実務（コード生成、リファクタリング、監査）を完璧にこなす実行部隊。

## 2. 徹底したコンテキスト純化と JIT (Just-In-Time) 知識注入
*   **Skill (振る舞い) と Zettelkasten (知識) の完全分離**:
    *   エージェントのプロンプト（`SKILL.md`）には、大局的なドメイン知識やプロジェクトの背景を決してハードコードしません。
    *   実行に必要なアーキテクチャ（`docs/architecture/`）や制約ルール（`docs/rules/`）は、実行の瞬間に静的DI（ファイルパスによる直接参照）を通じてインメモリでロードされます。これにより、AIの推論リソースを温存し、ハルシネーション（Lost in the middle）を防止します。

## 3. ドキュメントの階層化ライフサイクル（記憶の3層モデル）
ドキュメントはシステムの「記憶」であり、ライフサイクルに応じて完全に住み分けられます。
*   **Layer 1: 短期記憶 (揮発性の作業デスク)**: セッションごとの `task.md` や `progress.md`。AIの記憶喪失を防ぐ動的なチェックリストであり、作業完了後に揮発・または次レイヤーへ昇華されます。
*   **Layer 2: 中期記憶 (動的なプロジェクトルーム)**: `workspaces/` 上のEpic管理。AIが再起動・入れ替わっても進捗を見失わないためのHandoff（申し送り）領域。
*   **Layer 3: 長期記憶 (Timeless SSOT)**: `docs/` や `second-brain/` に保存される不変の真実。議論の過程（時系列）を一切排除し、確定したルールや仕様のみを保持する「法務局」。

## 4. System of Record (SoR) の明確な境界と単方向依存
*   **一方向の依存関係**: 「タスク ➡ 知識」の参照は許容されますが、「知識（SSOT） ➡ タスクID」の参照は厳禁です。システムは常に疎結合を保ちます。
*   **SoRの分離**: 外部からの制約（会議等）はGoogle Calendarを正本（Read-Only）とし、OS内部のタスク（筋トレ、自己研鑽）はSQLiteデータベースを正本（Write権限あり）とすることで、Agentが動的にパズルを解いてカレンダーに同期します。

## 5. JSON-First Protocol と Leave No Trace (ツール設計の極致)
*   **JSON-In / JSON-Out**: 全てのツールはシェルエスケープ事故を防ぐため、標準入力（stdin）からJSONを受け取り、JSONで結果を返します。
*   **インメモリ実行**: 一時ファイル（`scratch/tmp.md` 等）への書き出しは禁止。エラー時にもシステムにゴミを残さない「Leave No Trace」の原則が徹底されます。
*   **孤児ツールの即時浄化 (Garbage Collection)**: 呼び出し元の存在しないツールやスクリプトは技術的負債とみなされ、物理的なGitフックやCI監査によって即座に検知・自動削除されます。

## 6. 自律的ガバナンスと Quality Gates
*   **MakerとCheckerの分離**: 破壊的変更やコード生成はWorker（Maker）が担い、その結果はReviewer（Checker）がTimeless SSOTを基に厳格に監査します。
*   **多重防衛線**: セッション終了（Handoff）の絶対条件として、`core-service` 及び `agent-core` 双方におけるテスト（pytest）、リンター、SDD整合性監査の「Exit Code 0」が必須化されています。未検証のコードや状態の不整合は、システムへのマージが物理的にブロックされます。

## 結論
Agentic OSのTo-Be Stateは、「**制約と型（構造）をシステムに物理的に埋め込むことで、Agentの自由な思考と自律実行を極限まで高めた空間**」です。ルールはドキュメントとして陳腐化するのではなく、CIやJITルーティングを通じて「実行時に必ず強制されるOSの物理法則」として機能します。
