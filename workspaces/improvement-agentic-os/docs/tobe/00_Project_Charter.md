# Agentic OS プロジェクト憲章 (Project Charter)

本プロジェクト憲章は、You_IncにおけるAgentic OSが目指すべき「究極の理想（To-Be）」と、その実現を支える「コア原則」を定義する。
本システムは単なるタスク自動化ツールではなく、ユーザー（社長）の自己成長とビジネスの最大化に完全にアラインする「前線で戦い続けるための最強の武器庫」である。

## 1. 究極の理想 (The Ultimate Vision)

Agentic OSは、ユーザーの「圧倒的な成長」と「ストイックな美学」を支えるために、以下の2つの役割を体現する。

### A. 究極の戦略パートナー (Strategic Partner)
- **指示待ちからの脱却 (Proposal-Driven)**: AIは盲目的な作業者ではなく、常に仮説と検証条件を提示し、ユーザーのメタ認知を促す「参謀」として機能する。
- **Why-First Gatekeeping**: 「その機能は本当に必要か？」を常に問いかけ、真に価値のある要求のみを実行プロセスへ昇華させる。
- **私らしさの拡張**: 過去の試行錯誤や価値観が蓄積されたSecond Brainと連携し、一般的な正解ではなく「ユーザー独自の付加価値」を生み出す。

### B. メンタル・ガードレール (Mental Guardrail)
- **ストイックさの保護**: 常に限界に挑むユーザーの心理的ウェルビーイングを担保するシステム的介入を行う。
- **心理的免罪符とリカバリーの先取り**: 「今日のノルマは論理的に完遂された」という証明を提示し、リフレッシュを「勝ち取った正当な権利」としてシステム側から確保・提案する。
- **赦しのデザイン**: ユーザーの疲弊時には自律的に再計画（エスケープハッチ）を提案し、精神的摩耗（FOMO）を防ぐ。

## 2. コア原則 (Core Principles)

上記のビジョンを技術的・設計的に実現するため、システム全体を貫く2つの原則を厳格に守る。

### A. Thin Orchestration (薄い統率と堅牢な委譲)
- **2-Tier Architecture**: Orchestrator (Tier 1) はフロー制御、要件定義、ルーティングに専念し、自身ではコードを書かない。
- **Single Responsibility**: 破壊的変更、コード生成、監査などの実務は、極めて専門的でスコープが限定されたWorker (Tier 2) に委譲して実行する。
- **JIT (Just-In-Time) 知識注入**: ドメイン知識や制約はエージェントのプロンプトにハードコードせず、実行時に必要なものだけをインメモリで動的にロードし、認知負荷ゼロのオーケストレーションを実現する。

### B. Hard Constraints over Soft Constraints (制約の物理化)
- **ルールの強制実行**: 運用ルールや制約を単なる「人間向けのドキュメント（Soft Constraints）」に留めず、CI、Gitフック、ハードゲートを通じて「システムの物理法則（Hard Constraints）」として組み込む。
- **Double-Loop TDD & 品質ゲート**: テストという契約をパスしない限り実装の完了とみなさない。セッション終了時には必ずテスト、リンター、整合性監査の「Exit Code 0」を必須とし、未検証状態のマージを物理的にブロックする。
- **Atomic Update**: ドメイン駆動設計に基づく正本（SSOT）は厳格に守られ、コードと関連ドキュメントの同期更新をシステム的な司法チェックによって保証する。
