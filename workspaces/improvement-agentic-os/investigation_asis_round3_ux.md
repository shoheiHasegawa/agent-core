# ユーザー視点でのAs-IsシステムのUX負債調査 (UX & Cognitive Load Analysis)

本レポートでは、現在のAgentic OSアーキテクチャ（特にFat Orchestrationとツールの脆さ）が、**人間（ユーザー）**に対していかに高い認知負荷と手動介入を強いているかについて分析し、MUSTレベルのUX負債を特定する。

## 1. 認知負荷の現状 (Cognitive Load on Users)

### 1.1 肥大化した進捗管理ファイル (Fat Orchestration) の解読負荷
現在のシステムでは、エージェント間の連携や状態管理のために複雑で巨大な進捗ファイル（Progress files、Shared context files）が用いられている。
- **問題点**: エージェントがスタックしたりエラーを起こしたりした際、ユーザーはこの巨大なJSONやMarkdownファイルを直接読み解き、どこで状態が壊れたかを特定しなければならない。
- **UX影響**: 開発タスクそのものではなく、「エージェントOSのデバッグ」にユーザーの認知リソースが奪われる。

### 1.2 エージェント間のハンドオフにおける不透明さと介入の強制
- **問題点**: ツールが脆いため、タスクの受け渡し（Handoff）が頻繁に失敗する。システムが自動でリカバリできない場合、ユーザーが手動で状態を整え、次のエージェントにプロンプトで指示を出し直す必要がある。
- **UX影響**: 「完全自動化」を期待しているユーザーに対し、実際には「不安定なワークフローの監視・手動ルーティング」というマイクロマネジメントを強いている。

## 2. ツールの脆さがもたらす手動介入の常態化 (Fragile Tooling & Manual Intervention)

- **エラーハンドリングの欠如**: ツール実行時の軽微なエラー（フォーマット違い、パスの間違いなど）でエージェントが停止し、ユーザーに助けを求めるケースが多発している。
- **コンテキストの消失**: エラー発生時にコンテキストが適切に保存されず、ユーザーが直前のエージェントの作業結果を要約して次のエージェントに伝えるという「人間API」としての役割を担わされている。

## 3. 解決必須のUX負債 (MUST-Level Human-UX Debts)

以上の分析から、以下の項目をMUSTで解消すべきUX負債と定義する。

1. **人間の介入前提のハンドオフ設計の廃止 (Eliminate Manual Handoffs)**
   - システム自身がエラーを検知し、自律的にリカバリまたは適切なサブエージェントへルーティングする「Thin Orchestration」への移行が必要。
2. **人間に読ませることを前提としない状態管理 (Abstracted State Management)**
   - ユーザーに見せるのは「ハイレベルな進捗と結果」のみとし、内部のFat Contextをユーザーから隠蔽する（またはビジュアルダッシュボード化する）。
3. **ツールの堅牢化とフェイルセーフ (Robust Tooling)**
   - APIやツールの入力フォーマットエラーなどをエージェント自身で自己修復(Self-healing)する仕組みを標準搭載し、ユーザーへの不要なエスカレーションを防ぐ。

## 結論
現在のAs-Isシステムは、「ユーザーの作業を代行する」というより、「ユーザーにエージェントの管理作業を増やす」状態に陥っている。Cognitive Loadを劇的に下げるためには、オーケストレーションの軽量化とツールの自己修復能力の向上が急務である。
