# SKILL Taxonomy Draft (新・SKILL体系の設計案)

このドキュメントは、You_Incにおける人間の認知負荷（覚えるコマンドの数）を極小化し、Agentの作業品質を最大化するための新しいSKILL統廃合プランです。

---

## 1. コンセプト：「3つのボタン」モデル

あなたが日常の業務で使うインターフェース（コマンド）を、究極的に**以下の3種類だけに絞り込みます**。

### 🔘 ボタン1: `@workspace-architect` (プロジェクトの開始)
*   **用途**: 新しいEpic（開発や大きなタスク）を始める時。
*   **Agentの動き**: 必要なディレクトリ構造や、進捗管理用の `tasks/progress.md` を自動構築します。

### 🔘 ボタン2: `/grill-me` (壁打ち・意思決定)
*   **用途**: あなたが脳の汗をかく「介入度 [高]」のフェーズ。（SDD仕様策定、夜のTriageなど）
*   **使い方**: ` /grill-me docs/rules/zettelkasten_heuristics.md を使って今日のノートを蒸留したい ` のように、対象のルール（Heuristics）を指定して起動します。
*   **💡 独自ルール（Zettelkastenの質問スタイルなど）の認識方法**: 
    ネイティブコマンドに対して「どういうスタイルで壁打ちしてほしいか」を認識させるため、かつてSKILLとして記述していた質問スタイルは、単なるテキストファイル（例: `docs/rules/zettelkasten_heuristics.md`）に移行します。トリガー時にそのファイルのパスを含めるだけで、Agentは瞬時にそのスタイルを認識・憑依して壁打ちを行います。

### 🔘 ボタン3: `@session-manager` (実作業の半自動実行)
*   **用途**: 仕様やタスクが決まった後の「介入度 [低]」のフェーズ。
*   **トリガーの統合**: `@session-manager 次へ` と打つだけで、Agentは `progress.md` を読み込み、「Start/Resume/End」をファイルの状態から自動判定して動きます。
*   **💡 You_Inc独自の設計方針（DDD等）の認識方法**:
    ルーター（`session-manager`）から呼び出される「純化されたWorker SKILL（例: `tdd-worker`）」の中に、`必ず docs/architecture/ddd_guidelines.md を JIT (Just-In-Time) で読み込んでから実装せよ` という絶対の制約を記述しておきます。Workerはオーケストレーションの重い指示から解放されているため、この独自ルールを100%の注意力で読み込み、遵守することができます。

## 2. 階層的ループ（Loop Engineering）の実現アーキテクチャ

おっしゃる通り、実際の業務には「マクロなループ（外側）」と「ミクロなループ（内側）」が階層的に存在するため、これらを組み合わせたアーキテクチャが必要です。新しいシステムでは、以下の3層構造で階層ループを実現します。

### 🔄 第1階層：Macro-Loop (人間のトリガー ＋ progress.md)
*   **担当**: `@session-manager` と 人間
*   **粒度**: 「SDD(設計)」 ➡ 「TDD(実装)」 ➡ 「ZK(ナレッジ化)」といった一番外側の大きな工程。
*   **実現方法**: `progress.md` にチェックリストとして表現され、人間が `@session-manager 次へ` とトリガーを引くことでループが1つ進む。ここでAgentが迷子になることはありません。

### 🔄 第2階層：Meso-Loop (Workerによるマイクロループ)
*   **担当**: 純化されたWorker SKILL（例: `tdd-worker`）
*   **粒度**: TDDにおける「Red(テスト作成)」 ➡ 「Green(実装)」 ➡ 「Refactor」といった実務の中間ループ。
*   **実現方法**: 呼ばれた `tdd-worker` が、自身のSKILL内に書かれた手順に従い、一時的な `invoke_subagent` を使って「自分でコードを書き、自分でテストし、自分でレビュー用サブエージェントにチェックさせる」という自己完結型のループを回します。人間は介入しません。

### 🔄 第3階層：Ad-hoc Loop (自律チーム編成)
*   **担当**: ネイティブ機能 `/teamwork-preview`
*   **粒度**: 特定の難易度の高いタスク（例: アーキテクチャの評価など）における、Agent間の客観的な議論ループ。
*   **実現方法**: 必要な時に人間が明示的に `/teamwork-preview` を呼び出し、Agent同士の議論ループを発生させて結論だけを受け取ります。

👉 **結論**: 大きなループ（Macro）はファイルと人間のトリガーで安全に管理し、小さなループ（Meso/Micro）はWorker内部やネイティブ機能の局所的な自律性に任せる。これが「最もコンテキストが溢れにくく、かつ完全にルールを遵守できる」ループエンジニアリングの形です。

## 3. 既存20個のSKILLの「断捨離」マッピング

*   **🗑️ 廃止 (12個)**: `sdd-loop-orchestrator`, `sdd-spec-builder` 等はすべて `/grill-me` (＋ `docs/rules/*.md`) や `/teamwork-preview` に吸収。
*   **🔪 純化 (4個)**: `tdd-red-builder` 等は、階層的ループの「Meso-Loop（第2階層）」を担当する純粋なWorkerへ純化。独自ルール（DDD等）を読み込む制約だけを残す。
*   **👑 維持 (2個)**: `session-manager` (第1階層のルーター) と `workspace-architect` (環境構築)。
