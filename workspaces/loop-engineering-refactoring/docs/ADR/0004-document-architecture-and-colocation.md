# ADR 0004: ドキュメント配置戦略（Colocationと責務分離）

## Status
Accepted

## Date
2026-08-13

## Context
TO-BEのAgentic OS環境において、`agent-core`（OS）と`core-service`（プロダクト）の `docs/` ディレクトリに何をどう配置すべきか、そして機能仕様書（`spec.md`）はコードと混在させるべきか（分散配置）か、隔離すべきか（集合配置）について再定義が必要視された。

## Decision 1: `spec.md` の分散配置（Colocation）の完全肯定
**結論: `spec.md` などの機能仕様書は、コードと同一ディレクトリ（`src/` 配下）に「分散配置（Colocation）」することを公式標準とする。**

- **理由（Agentic観点）**: 
  Agentにとって、ドキュメントが `docs/spec/` のような「遠くのフォルダ」にあることは、ドキュメントの更新漏れ（Amnesia）の最大の原因となる。`GEMINI.md` が定める「Atomic Update（ドキュメント修正漏れはバグと同義）」を強制するためには、コードのすぐ横に `spec.md` が物理的に存在していることが最も強力な「物理的制約（Hard Constraint）」となる。
- **影響**: `core-service/docs/spec/` のような集合配置フォルダは負債として完全に廃止（パージ）する。

## Decision 2: 全リポジトリ共通の `docs/` 標準構造（型の統一）

リポジトリごとに `docs/` の構造が異なると、Agent（および人間）の認知負荷やルーティングエラー（ノイズ）の要因となる。そのため、`agent-core`、`core-service`、および将来の全リポジトリにおいて、**以下の統一された「You_Inc標準の `docs/` 構造（型）」を適用する。**

### 統一ディレクトリ構造 (The Unified Structure)

```text
docs/
├── rules/         # そのリポジトリ内で働くAgentが従うべき「制約・法律・ヒューリスティクス」
└── architecture/  # そのリポジトリの「地図・全体像・データフロー」
```

### 各ディレクトリの役割（リポジトリを問わず共通）

1.  **`docs/rules/` (制約と作法)**
    *   Agentが作業前にJITロードして読み込む対象。
    *   `agent-core` の場合: 全体共通のOSルールや、`/grill-me` 用の質問スタイル（Heuristics）が入る。
    *   `core-service` の場合: DDDの依存ルール、タイピング制約などのドメイン固有ルールが入る。
2.  **`docs/architecture/` (俯瞰図)**
    *   プロジェクトの全体像を把握するために読む対象。
    *   `agent-core` の場合: `data_flow.md` など、You_Incエコシステム全体の仕組み。
    *   `core-service` の場合: パッケージ構成やAPIの繋がりを示すアーキテクチャ図。

### ❌ 共通の禁止事項とライフサイクルの分離
*   **`docs/spec/` の恒久配置禁止**: どのリポジトリであっても、機能仕様書は必ず実行コード（`src/` や `skills/`）のすぐ横に分散配置（Colocation）しなければならない。
*   **`docs/ADR/` の恒久配置禁止**: ADR（アーキテクチャ決定記録）は、リポジトリに恒久的に残すべきではない。ADRは開発中の「意思決定のログ」に過ぎず、最終的な「根拠と結果」は必ず上記の `rules/` や `architecture/`、あるいは `second-brain` に吸収（統合）されなければならない（SSOTの原則）。
    *   👉 **ADRの正しい居場所**: プロジェクト実行中の一時的な `workspaces/<Epic名>/docs/ADR/` にのみ存在を許す。ワークスペース完了時のクリーンアップ作業において、AgentがADRを読み込んで正本ドキュメントを更新し、ワークスペースと共にADRは破棄される（Leave No Trace）。

## Consequences
- 「コードとドキュメントが混在する」という一般的なソフトウェア工学の懸念よりも、**「Agentが確実にドキュメントを更新できる（Contextの局所化）」というAI開発特有のメリットを優先**する。
- 役割が明確化されたことで、Agentは「どのルールを読めばいいか」を迷わなくなり、無駄なファイルの読み込み（トークン浪費）が激減する。
