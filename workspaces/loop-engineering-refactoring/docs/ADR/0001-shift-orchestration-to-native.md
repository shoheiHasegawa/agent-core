# ADR 0001: オーケストレーションのネイティブ機能への委譲と状態の外部化

## Status
Accepted

## Date
2026-08-13

## Context (課題・As-Is)
- **現状**: You_Incでは、TDDのループ進行や複数Agentの呼び出し（オーケストレーション）を、`sdd-loop-orchestrator` などの複雑な「SKILL（プロンプト）」内で無限ループとしてAgentに暗記・実行させようとしていた。
- **課題**: コンテキストウィンドウ（Agentの脳のメモリ）が手順管理のプロンプトに奪われ（Context Dilution）、実装フェーズにおいて「ディレクトリ構造が守られない」「設計方針が無視される」という品質低下が頻発している。
- **問題の核心**: Agentが「どこまで終わったか」「次に何をするか」をプロンプト内で記憶し続けようとした結果、読み忘れ・書き忘れ（忘却）が発生している。

## Decision (合意事項・To-Be)
1. **オーケストレーションと実作業の分離（ネイティブ機能への委譲）**
   - 「無限ループで自律稼働させる」ことをやめ、Antigravityのネイティブ機能（`/goal`, サブエージェント）に実行を委ねる。
2. **状態（現在地）の外部化とステートレス化**
   - Agentにフェーズを暗記させるのをやめる。
   - すべての進捗（現在地）は必ず `tasks/progress.md` に物理的に書き出し、Agentはステートレスなルーターとして振る舞う。
3. **人間のトリガーによる「Check-in / Check-out」の義務化**
   - **Check-in（読み込み強制）**: ユーザーが「`@session-manager 次へ`」とトリガーを引くことで、Agentは必ず最初に `progress.md` を読み込み、現在地を把握する。
   - **Check-out（書き込み強制）**: Agentのタスク完了条件（Exit Criteria）を、「`progress.md` を更新して終了すること」に限定し、そこで意図的に処理を止めて人間にレビューを求める。
4. **User Experience (人間の認知負荷低減)**
   - 明示的な呼び出しが必須になるため、人間が「どのSKILLを、どういう名前で呼べばいいか」迷わない設計が絶対条件となる。
   - 既存の細分化・複雑化しすぎたSKILLの粒度と命名規則を抜本的に見直し、「人間が少ない認知負荷でトリガーを引ける」インターフェースを構築する。

## Consequences (結果)
- **Positive**: 
  - Agentは「今やるべき1つのタスク」と「ルール」だけに100%のコンテキストを割けるため、作業品質（ディレクトリ構造の維持等）が劇的に向上する。
  - プロンプトがシンプルになり、読み忘れ・書き忘れが物理的に発生しなくなる。
- **Negative / Risks**: 
  - 人間が全く介在しない完全自動化は手放し、「人間が起点（次へ、の合図）を出す半自動」となる。

## Notes for Second Brain
- 本決定事項は、You_Incのエコシステム拡張における基本方針（Constitution）となる。
- 「OSの上にもう一つAgentic OSを作らない」「記憶はファイルに逃がし、Agentはステートレスに動かす」という原則を徹底すること。
