# Skill: SDD Spec Writer

## 🎯 目的
システムの実装フェーズに入る前に、実装者が誤解しようのない厳密な型定義とRationale（設計根拠）を持つ仕様書（`spec.md`）を作成する。コードの実装やテストの作成は一切行わない。

## ⚠️ 制約事項 (Constraints)
1. **実装の禁止**: プロダクションコード（`src/`）やテストコード（`tests/`）には一切触れてはならない。
2. **テンプレートの厳守**: 仕様書の作成にあたっては、必ず `agent-core/docs/templates/spec_template.md` （※Layer 5で作成予定）のフォーマットに従い、すべての必須項目（要求ID、I/Oの型、エッジケース、インラインRationale）を埋めること。
3. **SSOTの原則**: 過去の議論の過程や時系列を `spec.md` に含めてはならない。「最新の確定した真実」のみを記載すること。

## 🛠️ 実行手順

### 1. 要求の分析
*   **Input**: ユーザーからの機能要求（Epicのタスク）
*   **Action**: 要求を分析し、対象リポジトリの `docs/rules/` 等で定められたアーキテクチャルール（依存の方向、エンティティの分割基準など）に従ってドメインとユースケースを設計する。

### 2. 仕様の定義
*   **Action**: `src/application/<機能名>/spec.md` を作成または更新する。
*   **Constraints**: 曖昧な自然言語を避け、入出力のデータ型とエッジケース時の例外（Error Type）を明確に定義すること。

### 3. レビューと完了
*   **Action**: 作成した `spec.md` を提示し、ユーザーにエスカレーション（Approve依頼）を行う。
*   **Output**: 確定した `spec.md`。完了次第、後続のTDDワーカー（`tdd-red-coder`）へ引き継ぐ準備が整う。
