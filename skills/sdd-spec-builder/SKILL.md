# SKILL: SDD Spec Writer (Loop 1: Co-Creation Discovery)

このファイルは、特定のタスクを実行するための具体的な手法（Layer 3）を定義する。

## 🎯 目的 (ミクロな WHY)
なぜこのスキル（手順）が存在するのか。
- いきなり完成版の仕様を出力してしまう即答バイアスを防ぎ、必ず背景ヒアリングやエッジケースの壁打ちを強制することで、仕様の穴を実装前に確実に塞ぐため。
- 仕様書を「時系列や議論経緯を含まない最新の確定した真実（Timeless SSOT）」として保つため。
- 実装ループに進む前に、ユーザーの明示的な承認（Human Gate）を得るというフローを担保するため。

## 📥 入力と出力 (ミクロな WHAT)
※ ここでのWHATはシステム大局の目的ではなく、このスキル（関数）が受け取るべき「前提条件・インターフェースの制約」である。
- **Input**: ユーザーからの要求・課題・バグ報告
- **Output**: ユーザー承認済みの `spec.md` およびインポート可能なスタブ群（DTOやUseCaseクラス等）

## 🛠️ 実行手順 (HOW)
具体的にどうやってタスクを達成するか。
1. `agent-core/docs/rules/sdd_tdd_heuristics.md` を直接JITロードし、「なぜこの機能が必要なのか、最も解決したいユースケースは何か」を深掘りする。
2. 仕様の穴を突く反証可能な質問（エッジケース・境界値など）をユーザーに提示し、合意形成を行う。
3. 対話で合意された内容を `src/application/<機能名>/spec.md` に反映し、`src/application/<機能名>/` 配下に空のスタブを配置する。
4. [完了条件 / Exit Criteria] 作成した `spec.md` の要点を提示し、ユーザーから明示的な承認（Approve）を得る。承認後、親エージェントへ標準の形式で完了を報告する（独自の出力契約は使用しない）。
