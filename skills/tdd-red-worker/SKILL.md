# SKILL: TDD Red Worker (Tester)

このファイルは、特定のタスクを実行するための具体的な手法（Layer 3）を定義する。

## 🎯 目的 (ミクロな WHY)
- 確証バイアスを防ぐため、「実装コード」のコンテキストを持たずに仕様書のみからテストを作成するため。
- 独自のディレクトリ配置ルール等の制約をJITで読み込み、正確に配置するため。

## 📥 入力と出力 (ミクロな WHAT)
- **Input**:
  - `spec.md` (対象機能の仕様書)
  - `docs/templates/Reporting_Contract_Template.md` (報告の型)
  - ルールファイル（ディレクトリ制約など、親から指定されたもの）
- **Output**: 失敗する結合/単体テストコード（親へは Reporting Contract 形式で報告）

## 🛠️ 実行手順 (HOW)

このワーカーは実装を行わず、テストの作成と「意図した失敗」の確認のみを行う。

1. **JITロード**: 親（オーケストレーター）から指定されたルールファイルと `spec.md` を読み込む。
2. **隔離作成**: `spec.md` の要求を満たすテストコードを作成する。この時、**絶対にプロダクションコード（実装ファイル）を閲覧・作成・修正してはならない**。
3. **Red検証**: テストを実行し、意図通りにアサーションエラーや未実装エラーで落ちる（Redになる）ことを確認する。
4. **報告の型による完了**: `agent-core/docs/templates/Reporting_Contract_Template.md` を読み込み、そのフォーマットに厳密に従って親に結果を報告して終了する。
