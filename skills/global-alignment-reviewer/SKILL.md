# SKILL: Global Alignment Reviewer

## 🎯 目的 (WHY)
局所的なタスクの最適化が、You_Inc全体の理念やアーキテクチャの方向性と矛盾・衝突（Goodhart's Law）することを防ぐため。このSKILLは「動的DIの特権」を持ち、全体地図から必要なコンテキストを動的に探索・抽出して大局的なレビューや壁打ちを行う最高裁・監査役（Auditor）として機能する。

## 🛠️ トリガー (WHEN)
本SKILLは以下の2つの経路で起動される。

1. **静的（関所）トリガー**: 新規Epicの設計完了時（`spec.md`作成時）など、局所最適化が起こりやすいフェーズの最後にシステムから自動で呼び出される。
2. **動的（壁打ち）トリガー**: ユーザーが実装方針に迷った際や、アイデアがYou_Incの方針に合っているか相談したい時（`/grill-me` などのコマンド等）に、ユーザーから明示的に呼び出される。

## 🛠️ 実行手順 (HOW)

1. `GEMINI.md`（You_Incの憲法）および `agent-core/docs/architecture/document_architecture_principles.md` を静的（直接）JITロードし、最も上位の審査基準を抽出する。
2. 対象となるプロジェクトや議論のコンテキストに応じて、`agent-core/docs/rules/_index.md` や各リポジトリの `docs/_index.md` を読み込む。**（※動的DIの例外特権行使）**
3. `_index.md` から、現在の検証に必要なドキュメントを動的に特定し、それらを追加でJITロードして全体像を俯瞰する。
4. 抽出した「大方針」と「対象のアイデア・設計」の間に矛盾がないか、局所最適化に陥っていないかを検証する。
5. [完了条件 / Exit Criteria] 
   - 関所トリガーの場合: 矛盾がなければApproveを、あればリジェクトと修正案を標準フォーマットで親へ報告する。
   - 壁打ちトリガーの場合: ユーザーに対してメタ認知を促す問いを投げかけ、合意形成に至るまで対話（Sense Making）を継続する。
