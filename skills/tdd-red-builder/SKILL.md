# SKILL: TDD Red Coder (Tester)

このファイルは、特定のタスクを実行するための具体的な手法（Layer 3）を定義する。

## 🎯 目的 (ミクロな WHY)
なぜこのスキル（手順）が存在するのか。
- 実装コードに触れずテスト作成のみに専念することで確証バイアスを防ぐため。
- 仕様書の要求IDを網羅した「失敗するテスト」を先に作ることで、テスト自体の妥当性（防波堤としての役割）を担保するため。

## 📥 入力と出力 (ミクロな WHAT)
※ ここでのWHATはシステム大局の目的ではなく、このスキル（関数）が受け取るべき「前提条件・インターフェースの制約」である。
- **Input**: 対象機能の仕様書 (`spec.md`)
- **Output**: 失敗する結合テストコード (`tests/integration/<domain>/` 配下)

## 🛠️ 実行手順 (HOW)
具体的にどうやってタスクを達成するか。
1. `agent-core/docs/rules/sdd_tdd_heuristics.md` を直接JITロードし、対象機能の `spec.md` から全シナリオ（要求ID）を把握して、正常系・異常系のテストケースを抽出する。
2. `tests/integration/<domain>/` 配下に対象の結合テストコードを作成・更新し、各テスト関数の DocString に `[要求ID]` を明記する。
3. テストを実行し、構文エラーではなく意図通りにアサーション失敗等で落ちること（Red）を確認する。
4. [完了条件 / Exit Criteria] 意図的な失敗（Red）が確認できたら、標準の報告フォーマット（Reporting Contract）にて親エージェントへ報告し終了する（独自の出力契約は使用しない）。
