# 🧠 Zettelkasten & Socratic Dialog Principles (知識蒸留と対話の原則)

## 🎯 本ドキュメントの存在目的 (WHY)
社長の日常の意思決定やプロジェクトの気づき（ルートBの学び）を `second-brain` へ蓄積する際、**AIが先回りして教科書的で無難な一般論に要約してしまうことで、「社長自身の頭で内省して成長する機会」と「なぜその洞察に至ったかという生々しい熱量（Whyのエントロピー）」が奪われるのを防ぐため**。

---

## 1. WHAT：Zettelkasten ノートの品質基準（守るべき契約）

1. **アトミックノート蒸留境界**:
   - **WHY**: 1つのノートに複数のテーマや一過性の作業手順が混ざると、後から別の文脈と結合（リンク）できなくなるため。
   - **基準**: 1つの Permanent Note には「1つの普遍的な概念や法則」のみを記述する。リポジトリ固有の施工手順やアンチパターンは [`agent-core/docs/experiences/`](../experiences/README.md) へ振り分け、`second-brain` には混ぜない。
2. **厳格な YAML メタデータ**:
   - `id`: `YYYYMMDDHHMMSS` 形式
   - `tags`: 英語の `snake_case`、階層型（例: `#domain/agentic_organization`）。日本語や CamelCase は禁止。
   - `aliases`: 日本語の短い名詞句（2〜3単語）。
3. **弁証法的な双方向リンク**:
   - 関連ノートへのリンクは `[[...]]` を用い、単なる関連ではなく `[Conflict]`（対立）、`[Support]`（根拠）、`[Narrower]`（具体化）などの関係性を明示する。

---

## 2. HOW：ソクラテス式壁打ちと熱量保存のプロトコル

1. **Collision First（対立・矛盾からの問いかけ）**:
   - いきなりAIがまとめ案を書くのではなく、「一般論（または過去のノート）では〇〇と言われるが、今回の実体験ではなぜ△△という逆の結論になったのか？」という対比・矛盾を1〜2問投げかけ、社長自身の言葉で `WHY` を語らせる。
2. **思考の生鮮保存（AI要約による平滑化の防止 — `[EXP-06]`）**:
   - AI特有の綺麗に整った一般論に丸めてはならない。社長が語った生々しい比喩（例：「裸の王様化」「足し算バイアス」）、トレードオフの葛藤、具体例をそのままノートの核として残す。
3. **WHY ➔ WHAT ➔ HOW による普遍化**:
   - 個別の現象から「①なぜその問題が起きるのか（構造的WHY）➔ ②どうあるべきか（普遍的WHAT）➔ ③どう制御するか（実践的HOW）」の順で構造化し、他のビジネスや組織運営にも応用できる知的資産（IP）へ昇華させる。
4. **緊急時のフェイルファスト例外**:
   - 社長が単なる迅速なメモ記録（Inbox投入）や緊急対応を求めている時は、過度な深掘り対話を行わず即座に実行へ移る。
