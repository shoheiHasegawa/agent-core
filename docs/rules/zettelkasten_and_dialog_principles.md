# 🧠 Zettelkasten & Socratic Dialog Principles (知識蒸留と対話の原則)

本ドキュメントは、社長との内省壁打ち（ソクラテス式対話）および `second-brain`（Zettelkasten）へのノート蒸留において Agent が遵守すべき原則を定義する。

---

## 1. Zettelkasten 蒸留のベースライン（防護ネット）

1. **アトミックノート蒸留境界**:
   - 1つの Permanent Note には「1つの普遍的な概念や法則」のみを記述する。一過性の作業ログやリポジトリ固有の施工手順は `agent-core/docs/experiences/` へ振り分け、`second-brain` には混ぜない。
2. **厳格な YAML メタデータ**:
   - `id`: `YYYYMMDDHHMMSS` 形式
   - `tags`: 英語の `snake_case`、階層型（例: `#domain/agentic_organization`）。日本語や CamelCase は禁止。
   - `aliases`: 日本語の短い名詞句（2〜3単語）。
3. **弁証法的な双方向リンク**:
   - 関連ノートへのリンクは `[[...]]` を用い、単なる関連ではなく `[Conflict]`（対立）、`[Support]`（根拠）、`[Narrower]`（具体化）などの関係性を付与する。

---

## 2. ソクラテス式壁打ちとメタ認知のジャンプ（問いの立て方）

1. **Collision First（対立・矛盾からの出発）**:
   - 単なる要約や同意から始めず、「直感（または一般論）では〇〇に見えるが、今回の経験ではなぜ△△になったのか？」という対比・矛盾をぶつけ合わせるところから対話を始める。
2. **思考の生鮮保存（AI要約による平滑化の防止 — `[EXP-06]`）**:
   - AIとして綺麗な教科書的文章に丸めてはならない。社長自身の生々しい表現、トレードオフの葛藤、熱量（Whyのエントロピー）をそのまま核として残す。
3. **抽象度の引き上げ**:
   - 特定のツール名や一時的なプロジェクト名に縛られた記述を、「他のビジネスや組織運営にもそのまま適用できる普遍的な構造」へ引き上げる問いを投げかける。
4. **緊急時のフェイルファスト例外**:
   - 社長が単なる迅速なメモ記録や緊急対応を求めている時は、過度な深掘り対話（分析麻痺）を行わず即座に実行へ移る。
