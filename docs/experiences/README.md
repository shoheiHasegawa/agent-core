# 📚 Experiences & Precedents Stock (経験・失敗パターン・前例ストック)

ここは「SKILLは薄く、思考原則は鋭く、**経験（学び）は厚く**」の第3層（Layer C）である。
開発や運用の中で実際に発生した「Agentの失敗パターン（アンチパターン）」や「社長が下したリポジトリ運用上の前例（Precedents）」をここに厚くストックする。

---

## ⚖️ `docs/experiences/` と `second-brain/` の明確な振り分け基準

学びや気づきが生まれた際、どこに積むべきか迷わないよう以下の **「1秒判定テスト」** で厳格に区別する。

| 比較軸 | 🛠️ **`agent-core/docs/experiences/`（ルートA）**<br>＝ **社内の実務施工マニュアル・前例** | 🧠 **`second-brain/`（ルートB）**<br>＝ **社長個人の普遍的知見・思考資産 (IP)** |
| :--- | :--- | :--- |
| **1秒判定テスト** | **「次回、別のAgentがこのリポジトリで作業する時に、ミス防止や判断基準として参照させる必要があるか？」** ➔ **YES** | **「このコードベースを離れて、本業のマネジメント・講座・他ビジネスをする自分にとっても価値がある普遍的洞察か？」** ➔ **YES** |
| **具体例** | ・`tdd-red-worker` はプロダクションコードを見ない<br>・`core-service` の CLI は `src/entrypoints/cli/` に置く<br>・Worktree 内での親パス参照バグの防止策 | ・AIレビュアーの「無限指摘バイアス」と MUST/SHOULD/IMO による QCD 制御の法則<br>・権限委譲における「ブラックボックス化（裸の王様化）」と内省タッチポイントの設計論 |
| **書き手・承認** | **チームリーダーが自律追記 ➔ PRで事後承認** | **社長と秘書（`zk-distiller`）が壁打ちして言語化・蒸留** |

> 💡 **両方に該当する場合**: 「普遍的なマネジメント・設計思想（`second-brain`）」であり、かつ「社内の具体的な運用ルール（`docs/experiences/` または `docs/agent_rules/`）」でもある場合は、**抽象的な洞察を `second-brain` に蒸留し、具体的な施工ルールを `agent-core` に書く**。

---

## 🧭 運用ルール（チームリーダーへの指示）
1. **タスク着手時のJIT注入（Input）**:
   - チームリーダー（`team-leader`）は、メンバーへ作業を委譲する際、本ディレクトリ内の関連する経験ID（例：`[EXP-01]`, `[EXP-02]`）を特定し、参照先として渡すこと。
   - 未決事項が発生した際は、まずここの「前例（Precedents）」を確認し、類似の判断基準があれば **🟢 Tier 1（自律決定＆事後承認）** または **🟡 Tier 2（根拠付き推奨案の提示）** として処理せよ。
2. **クローズ時の還流（Output）**:
   - Epic完了時、`tasks/lessons_learned.md` に溜まった学びのうち、今後の別プロジェクトでも再発しうる具体的な失敗パターンや新たな社長判断（🔴 Tier 3 の裁定結果）を本ディレクトリのファイルへ追記して PR に含めよ。
