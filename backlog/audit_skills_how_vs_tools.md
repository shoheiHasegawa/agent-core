# 📝 Backlog: 全SKILLの「HOW固定」監査と、ツール強制vs推論解放の境界線策定

## 📖 Background (なぜやるのか / 背景と課題)
Zettelkastenの検索プロセスにおいて、SKILL内に「特定の検索ツールを使え」という『HOWの固定』があったことが判明した。これは他のSKILLでも同様に発生している可能性が高い。
一方で、「HOWを固定しない（AIの汎用推論に任せる）」ことと「専用ツール（tools）を強制する」ことには強力なトレードオフが存在する。ツールを通すことで、AIの推論による確率的な揺らぎ（ハルシネーション）を防ぎ、機械的な品質担保と再現性を確保できる側面もあるためだ。
現在、この「推論に任せるべきタスク」と「ツールで確実性を担保すべきタスク」の境界線が曖昧であり、システム全体でHOWの過剰固定や、逆に危険な推論解放が散見される恐れがある。

## 🎯 Goal & DoD (何を目指すのか / 完了条件)
- [ ] すべてのSKILL（`agent-core/skills/*`）を監査し、不必要に「HOW（特定のツール使用など）」を固定している部分を洗い出す。
- [ ] 「ツールによる処理（確実性の担保）」と「推論による作業（柔軟性の担保）」の境界線をどう折り合いをつけるか（トレードオフの裁定基準）を言語化し、`agent-core/docs/architecture/development_standard.md` 等のアーキテクチャガイドラインに追記する。
- [ ] 策定した基準に基づき、各SKILLのルール（HOWの縛り）をリファクタリングする。
